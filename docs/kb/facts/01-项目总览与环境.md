# 01 项目总览与环境

## 1. 项目是什么

HyperAlive（代码内包名 `org.aliveclean`，对外 APK 名 `AliveHS`）是 **OpenAlive HyperPort** 的 LSPosed 模块，目标是在 HyperOS 上实现：

- 桌面、锁屏、息屏（AOD）使用同一张“活”壁纸；
- 息屏时壁纸收成球体，保留 AOD 时钟/通知；
- 支持照片、相框、Cosmic、Vivo、Flyme 等壁纸场景；
- 提供 AliveHS 息屏样式、系统个性化入口、全屏 AOD、景深/指纹时钟等增强；
- 尽量不替代系统 UI，只补系统不提供的连续壁纸链路。

代码根目录：

```text
C:/Users/ybybabab/app/项目开发/HyperAlive
```

> 包名 `org.aliveclean` 是 native 符号、LSPosed 配置、历史数据共同依赖的硬约束，**不得改**。见 `PROJECT-CONSTRAINTS.md`。

## 5. LSPosed 作用域（当前结论）

| 作用域 | 是否必须 | 用途 |
|---|---|---|
| `com.android.systemui` | 必须 | AODView 注入、全屏 AOD、景深、锁屏触摸 |
| `com.miui.aod` | 必须 | AOD 设置页 AliveHS 样式、预览 |
| `com.android.thememanager` | 必须 | 系统个性化缩略图、预览 |
| `system`（系统框架） | 必须 | `AodWallpaperMode`、壁纸组件放行、`MiuiFullAodManager` |
| `android` | **不要勾** | 勾了会增加不必要注入/风险；历史约束明确禁止 |

### 5.1 不要勾 `android` 的原因

- `android` 是 framework 包，不等于 `system_server`；很多逻辑需要 `system` 作用域，而不是 `android`。
- 多勾会扩大 hook 面，增加崩溃/LSPosed 安全模式风险。
- 当前代码的 system_server 入口在 `AodWallpaperModeHook`、`DeviceIdleDelayHook`、两个 `checkPermission` hook，统一由 `system` 作用域承载。

### 5.2 API 102 的重启差异

- `com.android.systemui`：hook 后重启 SystemUI 可生效。
- `com.miui.aod`：杀进程/重启即可。
- `com.android.thememanager`：杀进程/重启即可。
- `system`：**必须重启手机**；`system_server` 不会因为 SystemUI 重启而重新加载模块。

### 5.3 常见环境错误

| 现象 | 原因 | 处理 |
|---|---|---|
| 应用壁纸报 `SecurityException: Selected service does not have android.permission.AMBIENT_WALLPAPER` | 没勾 `system` 作用域，或勾了但没重启 | 勾“系统框架”，重启手机；再应用 |
| 应用壁纸成功但 AOD 不出现 | `system` 作用域没生效；AOD 开关关闭；壁纸不是我们的 | 查 `dumpsys wallpaper`、`doze_always_on`、logcat |
| 设置页没有 AliveHS 行 | `com.miui.aod` 没勾/没重启；`Utils.isSupportFsAod` hook 未生效 | 勾 `com.miui.aod`，杀 AOD 进程 |
| 个性化缩略图灰白 | ThemeManager 未勾/未重启；provider 失败；hook 未命中 | 勾 ThemeManager，重启；查 `tm uf/ni7` 日志 |
| 装完还是旧行为 | APK 未真正替换；system_server 未重启；进程未重启 | 核对 SHA，重启手机 |
| （源码无 `RUNNING_LOCKED` 串，见 `../troubleshooting/03-作用域与权限排错.md` §3.2）锁屏时 `app_process` 读 Settings 失败/超时 | 设备锁屏，Settings provider 不可用 | 先解锁，再执行 `SceneApply` |

## 7. 术语

| 术语 | 含义 |
|---|---|
| AliveHS 样式 | 模块自定义的 AOD 样式；本质是“壁纸进程接管 AOD 球体 + 保留系统时钟” |
| 全屏 AOD / FS AOD | MIUI 的全屏息屏显示；原生只对系统壁纸/特定壁纸类型开放 |
| AodSurface | 注入 `com.miui.aod.AODView` 的 `TextureView`，显示 RenderLoop 的 AOD 画面 |
| AodOverlay | WindowManager 兜底窗口（type 2038）；当前被 appop 抑制，通常不是主路径 |
| 球体 | AOD 状态下由当前壁纸缩小/模糊/压暗形成的圆形区域 |
| 自定义 / 和锁屏样式一致 | MIUI AOD 设置里的两种模式；“自定义”是系统自己的 AOD 壁纸，不是 AliveHS 球 |
| 旧黑白月球图 | `/data/data/com.android.systemui/files/aod-wallpaper.png` 旧缓存；已从 RenderLoop 回退链删除 |
| `full_screen_aod_on` | MIUI Secure 设置；1 表示全屏 AOD 可用。模块会 capture/restore，不能永久写 |
| `doze_always_on` | 用户“息屏显示”总开关；关闭时任何 AOD 注入都应停止 |
