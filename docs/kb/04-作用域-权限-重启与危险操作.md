# 04 作用域、权限、重启与危险操作

> 本文件解决最常见的一类“代码改了但没效果”：**作用域没勾、勾错、没重启、进程没换。**
> 先读本文件，再怀疑代码。

## 1. LSPosed 作用域：最终结论

### 1.1 必须勾的四个

| 作用域 | 包名 | 主要职责 | 生效方式 |
|---|---|---|---|
| 系统界面 | `com.android.systemui` | AODView 注入、AodFullScreen、KeyguardDepthHider、KeyguardTouchRelay | 重启 SystemUI 或重启手机 |
| 息屏显示 | `com.miui.aod` | AliveHS 样式、AodWallpaperPreview、AodPreviewHider | 杀 AOD 进程或重启手机 |
| 主题壁纸 | `com.android.thememanager` | 系统个性化入口、缩略图 hooks | 杀 ThemeManager 或重启手机 |
| 系统框架 | `system` | AodWallpaperMode、AodFullScreen system_server 部分、SceneApply 权限放行 | **必须重启手机** |

### 1.2 不要勾的

| 作用域 | 结论 | 原因 |
|---|---|---|
| `android` | **不要勾** | `android` 是 framework 包，不是 `system_server`；多勾扩大 hook 面，增加崩溃/安全模式风险，且当前代码不需要 |
| 其他 app | 不要勾 | 当前代码只监听上述四个进程；多勾没有收益 |

> 用户明确要求记录：**只需要“系统框架”，不需要“安卓系统”作用域。**
> 如果 LSPosed 中文界面把 `system` 显示成“系统框架”，把 `android` 显示成“安卓系统”，请按包名勾，不要按中文名猜。

**产物侧佐证（2026-11-15 23:0x 核）**：b1c 的 APK 里 `META-INF/xposed/scope.list` 与 `app/res/values/strings.xml` 的 `xposed_scope` 都只声明这四个包，**没有 `android`**：

```text
scope.list:       com.android.systemui / com.miui.aod / com.android.thememanager / system
xposed_scope:     system / com.android.systemui / com.miui.aod / com.android.thememanager
module.prop:      minApiVersion=102, targetApiVersion=102, staticScope=true
```

配合 `tools/build_release.py` 的改动（本提交 `87f1613` 已包含）：原先把 `android` 写进 scope.list 的旧行为已修正为 `system`。注意：这只说明**模块声明**了什么，不等于设备上 LSPosed 里实际勾选的集合——后者只能在设备上确认（本轮设备未连接）。

### 1.3 作用域验证

```bash
# 看进程是否在
adb shell ps -A | grep -E 'systemui|miui.aod|thememanager|system_server'

# 看 LSPosed 日志（路径因版本而异，常见 /data/adb/lspd/log/）
adb shell su -c 'ls -l /data/adb/lspd/log/'
adb shell su -c 'tail -100 /data/adb/lspd/log/modules.log'
```

模块日志出现这些才算加载：

```text
AliveHSHooks: ... system_server ...
AliveHSHooks: full aod hooks=...
AliveHSAod: ... injected into the AOD view
AliveHSHooks: tm uf hook count=...
```

如果一条都没有：先查作用域/重启，不要改代码。

### 1.4 作用域是否真的生效：用留存日志反查

`.tmp/logs/lspmod.log`（LSPosed 框架日志，2026-11-14 15:51–15:54）里 `(system)` 段的 515 行属于其它模块，**`org.aliveclean` 的 `(system)` 行为 0 行**；同一时段的 `com.android.systemui`(33)、`com.miui.aod`(12)、`com.android.thememanager`(7) 都有 `org.aliveclean` 记录。

而 `.tmp/aod-evidence/**`（2026-11-15 10:2x–10:4x）里有 `(system)[org.aliveclean,AliveHSHooks,...] device idle: no-activity armed` 的命中。

- 结论：【已验证（历史）】2026-11-15 上午 `system` 作用域确实加载过本模块；【证据不足】2026-11-14 那次是否勾了 `system`；【证据不足】b1c 重启后 `system` 是否仍加载（无 16:0x 之后日志）。
- 方法建议：以后每次“勾作用域/重启”都把 `lspmod.log` 或 `adb logcat -d -s LSPosedFramework` 落盘到 `.tmp/logs/`，日期命名，别只写结论。


## 2. 重启语义（API 102）

用户要求明确记录：

> LSP API 102 除“系统框架”外，系统界面等作用域的 hook 无需重启手机。

准确表述：

| 改动作用域 | 是否需要重启手机 | 最小操作 |
|---|---|---|
| `com.android.systemui` | 否 | 杀 SystemUI 进程，等它自动重启 |
| `com.miui.aod` | 否 | 杀 `com.miui.aod` 进程 |
| `com.android.thememanager` | 否 | 杀 ThemeManager 进程 |
| `system` | **是** | 重启手机；`system_server` 不会因 SystemUI 重启而重新加载模块 |

注意：

- “无需重启手机”不等于“无需重启进程”。改完 APK 后，旧进程仍加载旧代码。
- `force-stop com.android.systemui` 有时不会真正换 PID（历史踩坑：PID 32258 未变），要用 `ps` 确认新 PID；必要时 `su 0 kill -9 <pid>`。
- 装完 APK 后如果动了 `system` 作用域代码，**直接重启手机**最稳，不要省。

### 2.1 常用重启命令

```bash
ADB="$LOCALAPPDATA/Android/Sdk/platform-tools/adb.exe"
D=9eb96e8a

# SystemUI
"$ADB" -s $D shell su 0 killall com.android.systemui
# 或 force-stop 后确认 PID 变了
"$ADB" -s $D shell am force-stop com.android.systemui
"$ADB" -s $D shell ps -A | grep systemui

# AOD
"$ADB" -s $D shell su 0 killall com.miui.aod

# ThemeManager
"$ADB" -s $D shell su 0 killall com.android.thememanager

# 整机
"$ADB" -s $D reboot
```

## 3. 权限与 root

### 3.1 `AMBIENT_WALLPAPER`

`SceneApply` 用 `su 1000` + `app_process` 调 `WallpaperManager.setWallpaperComponentWithFlags`。如果 `system` 作用域没生效，会报：

```text
java.lang.SecurityException: Selected service does not have android.permission.AMBIENT_WALLPAPER
```

处理顺序：

1. LSPosed 勾 `system`（系统框架），不是 `android`；
2. 重启手机；
3. 解锁设备；
4. 重新应用壁纸；
5. 仍失败再查 `checkPermission` hook 是否加载。

### 3.2 `RUNNING_LOCKED`

设备锁屏时，`app_process` 的 Settings provider 可能不可用，`Settings.Secure` 读取失败，表现为 `RUNNING_LOCKED`/空值。测试 `SceneApply` 前先解锁。

> **2026-11-15 22:40 复核（重要）**：`RUNNING_LOCKED` 这个字符串**在当前源码和 `docs/port/` 旧文档里都不存在**，只在 `docs/kb/` 里被反复引用（来源疑似上一轮 AI 自行生成）。`SceneApply` 的失败判据是“退出码非 0 / 输出不含 `SCENE_APPLIED`”，不会打印它。
> - 结论：【不支持】把它当成可匹配的错误串；【待验证】“锁屏时读 Settings 失败”这个机理。
> - 正确做法：先解锁再应用；失败时贴子进程原始输出，而不是 grep `RUNNING_LOCKED`。

### 3.3 root 授权

- `su 1000 -c ...`：切到 system uid 执行；
- `su 0 -c ...`：root 执行（仅用于测试/读取私有键）；
- 模块自身不应长期依赖 root 做 UI 操作；
- root 命令失败要打印 stderr，不要只看 exit code。

### 3.4 appop / overlay

`AodOverlay` 用 `TYPE_APPLICATION_OVERLAY`（2038）兜底，但 MIUI 可能因 `OPSTR_SYSTEM_ALERT_WINDOW` 拒绝。日志：

```text
AliveHSAod: overlay add failed ... appop
```

结论：overlay 不是主路径，AodSurface 失败时不要只靠 overlay。不要为了让它工作去永久改 appops；那是危险操作，必须记录到 `09-*`。

## 4. 文件与目录权限

| 路径 | 谁能读 | 说明 |
|---|---|---|
| `/data/data/org.aliveclean/files/photo` | 模块 app | 当前照片；SystemUI 直接读不到 |
| `/data/data/com.android.systemui/files/aod-wallpaper.png` | SystemUI | 旧缓存；已从 RenderLoop 回退链删除，但旧版本可能残留 |
| `content://org.aliveclean.aodphoto/photo` | 授权进程 | AodWallpaperProvider 暴露给 SystemUI/AOD |
| `/data/user_de/0/com.miui.aod/files/templates/current/` | AOD/root | MIUI 模板；provider 可能 root 复制 |
| `SharedPreferences scene` | 模块 app | 已应用场景；provider 独立进程需跨进程可见 |

常见错误：SystemUI 直接 `File` 读 `/data/data/org.aliveclean/files/photo` → `EACCES`。必须走 provider。

## 5. 危险操作清单

以下操作在手机上默认**禁止**，除非用户明确授权并记录：

| 操作 | 风险 | 替代 |
|---|---|---|
| `setprop` / 改系统属性 | 永久/影响系统行为 | 用 hook/临时设置；必须记录 |
| `settings put` 永久改 AOD 键 | 用户设置被覆盖 | 模块 capture/restore；测试后恢复 |
| 删除系统 APK/配置 | 系统不稳定/无法开机 | 不删除；用禁用/恢复 |
| 改 SELinux/permissions | 安全风险 | 不改 |
| 格式化/data | 数据丢失 | 不做 |
| 卸载系统应用 | 系统缺组件 | 不卸载 |
| 写 `/system` | 可能无法开机 | 不做 |

### 5.1 允许的临时测试

- `settings put secure doze_always_on 0/1`：测试 AOD 开关，测完恢复；
- `settings put secure full_screen_aod_on 0/1`：仅调试，测完恢复；
- `am force-stop`/`kill`：重启进程；
- 安装/卸载**本项目 APK**：可回滚。

每次临时测试必须写 `09-系统变更与危险操作记录.md`：

```text
日期/时间：
设备：
操作：settings put secure doze_always_on 0
原值：1
新值：0
原因：验证 AOD 关闭守卫
恢复：settings put secure doze_always_on 1
恢复验证：settings get = 1
备注：无 setprop
```

## 6. 环境排错顺序（不要跳）

```text
1. adb devices / 解锁 / root 可用
2. APK 是否真装（SHA/versionName）
3. 四个作用域是否勾对（system 不是 android）
4. system_server 是否重启（整机）
5. SystemUI/AOD/ThemeManager 是否换 PID
6. 壁纸是否是 CleanWallpaper（dumpsys wallpaper）
7. doze_always_on / full_screen_aod_on
8. 日志是否出现模块 tag
9. 才看代码
```

## 7. 常见“不是 bug”的情况

- 设备锁屏时执行 `SceneApply` → 子进程读 Settings 失败/超时（具体输出见 §3.2，**不要**假定有个 `RUNNING_LOCKED` 串）；
- 安装 APK 后没重启 system_server → AOD 关闭仍写 1；
- 只重启 SystemUI → `system_server` 仍旧代码；
- 系统静态壁纸下 MIUI 原生只支持“自定义” → 可能是产品限制；
- 系统壁纸切换没有走 `SceneApply` → 不能期待模块 capture/restore 立即执行；
- 录屏不显示 AOD 注入层，但 `screencap` 能看到 → 安全窗口/合成差异；
- 主题页坐标点击无效 → 页面滚动/弹层/overlay，不是缩略图 hook 失败。

## 8. 安全模式/崩溃

LSPosed 连续崩溃可能触发安全模式，表现为所有模块失效。处理：

1. 重启；
2. 进 LSPosed 禁用模块；
3. 查 `/data/adb/lspd/log/` 和 `logcat` 的 `FATAL EXCEPTION`；
4. 回滚到上一个 APK；
5. 不要在高频 hook（draw/帧循环）里抛异常。

## 9. 记录要求

任何系统级变更、删除、权限修改、`settings put`、`setprop`，必须写 `09-系统变更与危险操作记录.md`。没有记录 = 没发生，下一任 AI 会重复踩坑。
