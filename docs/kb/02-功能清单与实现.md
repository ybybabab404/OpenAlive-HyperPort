## 2. AliveHS 息屏样式：显示与锁定

### 2.1 用户看到的行为

- 使用项目壁纸时，`com.miui.aod` 的 AOD 设置页“息屏样式”行显示 **AliveHS 样式**；
- 该行被锁定，不能改回系统“自定义”；
- 切回系统壁纸后，行恢复原生 adapter，不再锁定。

### 2.2 实现入口

`app/java/org/aliveclean/AodSettingsGuard.java`

- `bind(View root)`：在 AOD 设置页 `onResume`/`onViewAttached` 后查找 `aod_resting_screen_style` 行和 `aod_resting_screen_choose` Spinner；
- 只有 `AodWallpaperMode.uiAlive(context)` 为 true 时才包装；
- `applyLabel(...)` 用 `LabelAdapter` 在原生列表里**第 2 项位置（index 1，即原生首项之后）**插入“AliveHS 样式”；
  - 复核：`AodSettingsGuard.java:353` 为 `this.labelPosition = base.getCount() > 1 ? 1 : 0;`，即原生只有 1 项时才放 index 0。旧文本写的“在原生 adapter 前插入”不准确。
- `lock(row, spinner)` 禁触摸/点击；
- `unbind(...)` 在壁纸不是我们的时恢复原 adapter 和可点击状态。

关键代码（节选）：

```java
private static void bind(View root) {
    Context context = root.getContext();
    if (context == null) return;
    int rowId = id(context, "aod_resting_screen_style");
    int spinnerId = id(context, "aod_resting_screen_choose");
    if (rowId == 0 || spinnerId == 0) return;
    View row = root.findViewById(rowId);
    View value = root.findViewById(spinnerId);
    if (!(value instanceof Spinner)) {
        Saved stale = SAVED.get(root);
        if (stale != null) unbind(root, stale);
        return;
    }
    Spinner spinner = (Spinner) value;
    if (!AodWallpaperMode.uiAlive(context)) {
        Saved stale = SAVED.get(root);
        if (stale != null) unbind(root, stale);
        return;
    }
    Saved saved = SAVED.get(root);
    if (saved == null) {
        saved = new Saved(row, spinner);
        SAVED.put(root, saved);
    }
    applyLabel(context, spinner, saved);
    lock(row, spinner);
}
```

`LabelAdapter` 的核心是“原生 adapter + 一个自定义项”：

```java
private static final class LabelAdapter extends BaseAdapter {
    private final SpinnerAdapter base;
    private final int labelPosition;

    @Override public int getCount() { return base.getCount() + 1; }

    @Override public Object getItem(int position) {
        if (position == labelPosition) return "AliveHS 样式";
        return base.getItem(position < labelPosition ? position : position - 1);
    }
    // getView/getDropDownView 同理：labelPosition 用自定义布局，其余委托 base
}
```

### 2.3 为什么需要 `AodFullScreen` 的 settings hook

如果 `com.miui.aod.Utils.isSupportFsAod()` 返回 false，MIUI 会直接不创建这一行/Spinner，`AodSettingsGuard` 就没有对象可包装。因此 `AodFullScreen.install(loader, true)` 在 AOD 进程只 hook 两个 support 方法：

```java
count += hookAliveTrue(clazz, "isSupportFsAod");
count += hookAliveTrue(clazz, "isInnerScreenSupportFsAod");
```

`hookAliveTrue` 只在“壁纸是我们的 + AOD 开关开启”时 `setResult(TRUE)`，切回系统壁纸后让原生结果生效。

- logcat：`full aod hooks=... process=aod`；

### 2.5 失败模式

| 现象 | 可能原因 |
|---|---|
| 没有 AliveHS 行 | `com.miui.aod` 未勾/未重启；`Utils` hook 未命中；`AodWallpaperMode.uiAlive` 为 false |
| 行出现但可点击/切回自定义 | 只包装了显示，`lock` 被系统重建 View 覆盖；或 `AodSettingsGuard` 未重新 bind |

## 3. 息屏球体：AodSurface 注入

### 3.1 期望链路

```text
电源键/超时
  → MiuiDozeService.onDreamingStarted
  → MIUI 创建 com.miui.aod.AODView
  → HyperOsAod 的 View 添加 hook（AODView attach）
  → scheduleAttach(950ms)
  → attach(AODView)
  → 创建 AodSurface(TextureView)
  → target.addView(surface, index=1)
  → SurfaceTexture available
  → new RenderLoop(moduleContext)
  → loop.mode(0) + loop.attach(surface)
  → RenderLoop 每帧画 AOD 场景（球/时钟底图）
  → 首帧后 alpha 0→1 / 180ms
```

### 3.2 代码

`app/java/org/aliveclean/HyperOsAod.java:19` 延迟：

```java
private static final long ATTACH_DELAY_MS = 950;
private static final long FADE_MS = 180;
```

`attach` 的关键部分：

```java
private static void attach(ViewGroup root) {
    final long generation = attachGeneration;
    Context context = root.getContext();
    aodRoot = new WeakReference<>(root);

    if (!aodEnabled(context)) { detach(); return; }
    if (!aodSceneEnabled(context)) { detach(); return; }
    if (!AodWallpaperMode.alive(context)) { detach(); return; }

    AodSurface existing = liveSurface == null ? null : liveSurface.get();
    if (existing != null && existing.isAttachedToWindow() && existing.isShown()) {
        return; // 已有表面，直接跳过
    }

    ViewGroup target = findInnerAod(root);
    if (target == null) {
        root.postDelayed(() -> injectIntoAod(), 200);
        return;
    }

    AodSurface surface = new AodSurface(context);
    surface.setTag(TAG);
    surface.setAlpha(0f);
    target.addView(surface, Math.min(1, target.getChildCount()),
            new ViewGroup.LayoutParams(MATCH_PARENT, MATCH_PARENT));
    liveSurface = new WeakReference<>(surface);
}
```

`AodSurface` 是 `TextureView`：

```java
private static final class AodSurface extends TextureView
        implements TextureView.SurfaceTextureListener {
    AodSurface(Context context) {
        super(context);
        appContext = moduleContext(context);
        setSurfaceTextureListener(this);
        setOpaque(true);
        setOutlineProvider(...椭圆...);
        setClipToOutline(true);
    }

    @Override public void onSurfaceTextureAvailable(SurfaceTexture texture, int w, int h) {
        surface = new Surface(texture);
        loop = new RenderLoop(appContext);
        loop.onFirstFrame(() -> post(() ->
                animate().alpha(1f).setDuration(FADE_MS).start()));
        loop.mode(0);
        loop.attach(surface, w, h);
    }
}
```

### 3.3 关键设计选择

- **不透明**：`setOpaque(true)`，避免 native AOD 壁纸透出来；但也意味着如果 RenderLoop 没画出有效内容，用户会看到黑块/变暗。
- **裁剪成椭圆**：`Outline.setOval`，球体位置/半径由 `BALL_CENTER_Y=0.165`、`BALL_RADIUS=0.22` 决定。
- **alpha 淡入**：首帧后才从 0 到 1，避免黑帧闪一下；如果首帧永远不来，surface 永远透明，用户看不到球。
- **插在 index=1**：`AODView` 的 index 0 是不透明黑底，index 1 是时钟/内容容器之前，保证球在背景上、时钟下。若层级和假设不符，球可能被黑底/内容盖住。

### 3.4 当前已知 bug

见 `03-已知Bug与排错.md` 的 **Bug A**。最关键的两个代码事实：

1. `supervise(...)` 方法存在，但**从未被调用**（`HyperOsAod.java:199` 只有定义）。它本应在 AODView 重建/移除后把 surface 重新挂回去。
2. `attach` 发现 `existing.isAttachedToWindow() && existing.isShown()` 就直接返回，不检查 alpha 是否为 1、RenderLoop 是否真的出帧。如果 surface 还在但纹理黑/透明，永远不会重试。

这可以解释“转场时看到球，稳定息屏只剩时钟”：转场阶段 surface 还在；MIUI 重建 AODView 后 surface 被移除，没有 supervise 重挂；或者 surface 在但 alpha/纹理没恢复。

### 3.6 2026-11-15 22:40 复核补正（读源码后修正三处）

1. **注入 hook 监听两个类名，不只 `com.miui.aod.AODView`**：
   `HyperOsAod.java:22-25` 的 `VIEWS` 数组是 `{"com.android.keyguard.widget.AodView", "com.miui.aod.AODView"}`，对两者都 hook 构造器。旧文本只写 `com.miui.aod.AODView`，排查时容易漏掉另一个类名。
2. **`AodOverlay` 不是“没在用的兜底”**：
   `HyperOsAod.installDoze(...)` 在 `MiuiDozeService.onDreamingStarted` 的 after-hook 里调用 `AodOverlay.show(svc)`，`onDreamingStopped` 里调用 `AodOverlay.hide()`（`HyperOsAod.java:44-68`）。也就是说每次息屏都会走 overlay 的 `show()`，它内部先试 `injectIntoAod()`，失败才退到 2038 窗口。
3. **`injected into the AOD view` 这条日志不能当作“注入成功”的证据**：
   它由 `AodOverlay.show()` 打印（`AodOverlay.java:31`），而 `HyperOsAod.injectIntoAod()` 只在 `aodRoot != null` 时返回 `true`，并不检查 surface 是否真的加进了 AODView。真正能证明注入的日志是 `Trace` 的 `T04 surface#create id=... host=... children=...`（`HyperOsAod.java:192-194`）。
   - 这一条直接改写 `03-*` §1.5 判定树里“有 injected 但稳定后无球”的推理前提：出现该日志时可能压根没注入。

补充确认（原文描述基本准确，这里补上细节）：

- `attach` 的早退条件确实是 `existing.isAttachedToWindow() && existing.isShown()`（`HyperOsAod.java:149`），不看 alpha、不看是否出帧。
- `supervise`（`HyperOsAod.java:199`）是 300ms 一轮、最多 100 轮（约 30 秒）；`getParent()==null` 要**连续 8 次 miss** 才重挂，不是“一空就挂”，且重挂后不会停表。
- `attach` 里 `findInnerAod` 失败时还会 `postDelayed(…, 200)` 调 `injectIntoAod()` 再试一次（`HyperOsAod.java:174-188`），所以“注入只尝试一次”的说法不准确——是 950ms 后尝试一次，找不到 inner 时再以 200ms 为间隔接力重试（受 generation 校验保护）。

## 4. 全屏 AOD：AodFullScreen

### 4.1 背景

MIUI 的原生全屏 AOD 只对“系统支持的壁纸类型”开放。第三方活壁纸通常被 `MiuiFullAodManager.isWallpaperTypeSupport` 判 false，导致：

- AOD 设置页隐藏全屏样式；
- 息屏后不进入全屏 AOD，只显示时钟/黑底；
- 模块需要在不永久改系统标志的前提下，临时让 MIUI 认为支持。

### 4.2 代码

`app/java/org/aliveclean/AodFullScreen.java`

两个消费者：

- `system_server` 的 `MiuiFullAodManager` 需要 `isDeviceSupport`、`isWallpaperTypeSupport`；
- `com.miui.aod` 设置页需要 `Utils.isSupportFsAod()`。

`install(loader, settingsProcess)`：

```java
if (settingsProcess) {
    hooks += hookSupport(loader);          // Utils.isSupportFsAod / isInnerScreenSupportFsAod
} else {
    hooks += hookManager(loader);          // MiuiFullAodManager 构造
    hooks += hookInitializer(loader);      // SystemUIInitializer.init
    hooks += hookWallpaperType(loader);    // isWallpaperTypeSupport
    hooks += hookDoze(loader);             // onDreamingStarted 前强 mFullAodEnable
}
```

`hookAliveTrue` 的条件：

```java
Context context = Xp.currentApplication();
if (context != null
        && AodWallpaperMode.alive(context)
        && HyperOsAod.aodEnabled(context)) {
    param.setResult(Boolean.TRUE);
}
```

`onActivation` 的 AOD-off 分支：

```java

    AodWallpaperMode.restore(context);
    syncFlags("activation-aod-off", context);
    forceManager(lastManager.get(), context);

```

### 4.3 为什么系统壁纸下会“始终自定义”

高置信推断：

1. `AodWallpaperMode.alive(context)` 只看 **system 壁纸槽的 `getWallpaperInfo()`**；
2. 系统静态壁纸返回 `null` → `alive=false`；
3. `AodSettingsGuard` 的 `uiAlive=false`，不包装 AliveHS 行；
4. `AodFullScreen` 的 `hookAliveTrue` 不再强制 true，MIUI 原生 `isWallpaperTypeSupport` 按系统壁纸类型返回；
5. 对 MIUI 静态壁纸，原生可能只允许“自定义”AOD，不允许“和锁屏样式一致/全屏 AOD”；
6. 结果就是用户看到“无论怎么设置都是自定义”。

这不一定是 bug，可能是 MIUI 对静态壁纸的限制；但用户明确期望系统壁纸下也能设置。需要先验证 `MiuiFullAodManager.isWallpaperTypeSupport` 的原始返回，再决定是“产品限制”还是“模块恢复逻辑丢失”。

## 5. AOD 壁纸 Provider

### 5.1 作用

SystemUI / AOD 预览不能直接读模块私有目录，因此模块提供 `content://org.aliveclean.aodphoto/...`（`AodWallpaperProvider`）给外部读当前 AOD 图。

### 5.2 代码

`app/java/org/aliveclean/AodWallpaperProvider.java`

读取顺序（当前）：

1. `scene` 的 `photo`；
2. `scene.preview` 的 `photo`（未应用草稿）；
3. `templateCache` 下的 `wallpaper_home` / `wallpaper`（root 从 MIUI 模板目录复制，3 次，每次 3s 超时）。

关键约束：

- 旧缓存 `aod-wallpaper.png` 不再作为 RenderLoop 的共享回退；
- `openFile` 失败返回 null，不抛异常；
- 复制前先删旧文件，避免“复制失败但旧文件还在”的假成功；
- 该 provider 在独立进程，读 SharedPreferences 需要 `MODE_MULTI_PROCESS`/跨进程可见性；`SceneOptions` 已处理。

### 5.3 验证

```bash
adb shell content read --uri content://org.aliveclean.aodphoto/photo > /tmp/aod.jpg
adb shell logcat -d -s AliveClean | grep 'aod photo from provider'
```

预期日志：`aod photo from provider 1200x2608`。

### 5.4 失败模式

| 现象 | 原因 |
|---|---|
| 球是旧黑白月球 | provider 失败后回退旧缓存；当前已删该回退，但旧 APK/旧缓存仍可能 |
| 球是系统壁纸而非项目图 | provider 读到了 templateCache 或系统模板，不是 APPLIED.photo |
| 球黑屏 | provider 返回 null、RenderLoop 上传失败、AodSurface 不透明 |
| 首次打开慢 | root 复制 3×3s 超时 |

## 6. 系统个性化缩略图

### 6.1 用户看到的行为

系统“个性化”页的锁屏/桌面预览卡片应显示当前项目壁纸，而不是灰白占位图。

### 6.2 实现

`app/java/org/aliveclean/AodWallpaperPreview.java` 在 ThemeManager 进程 hook 多个方法：

- `TemplateApiImpl.getPlaceholderWallpaper`
- `TemplateApiImpl.ni7`
- `TemplateApiImpl.uf`
- `Screenshots.t8r`
- `LockScreenWpTool.toq`
- `DeskWpTool.toq`

核心：

```java
Bitmap preview = forHook(context);
if (preview == null) return;
Bitmap replacement = original == null ? preview
        : scaleOrRecycle(preview, original.getWidth(), original.getHeight());
param.setResult(replacement);
```

`forHook` 对 cached bitmap 做防御性 copy；`scaleOrRecycle` 回收缩放产生的临时 bitmap，避免宿主 recycle 共享缓存导致 OOM/崩溃。

### 6.3 灰白占位的根因

旧版本 `getPlaceholderWallpaper`/`ni7`/`uf` 在 `original == null` 时直接 return，导致：

- ThemeManager 拿不到 replacement，继续显示自己的灰白占位；
- 或者 `ni7` 已把 bitmap 写进 wallpaper layer，after-hook 改返回值无效。

当前已改成 null 时返回 `preview`，并在 `t8r` 写回 `f53958zy` 字段。b1c 实测未复现灰白。

## 7. 应用项目壁纸：SceneApply

### 7.1 为什么需要 root

`WallpaperManager.setWallpaperComponentWithFlags` 需要 `AMBIENT_WALLPAPER` 权限；普通 app 没有，因此用 `su 1000`（system uid）+ `app_process` 调系统 API。

### 7.3 失败模式

| 报错/现象 | 原因 | 处理 |
|---|---|---|
| `AMBIENT_WALLPAPER` | 没勾 `system` 作用域，或勾了没重启 | 勾系统框架 + 重启 |

## 8. AOD 模式 capture/restore

### 8.1 键

| 键 | 含义 |
|---|---|
| `full_screen_aod_on` | MIUI 全屏 AOD 开关 |
| `alive_aod_restore_value` | 进入前原值（0/1/-1） |
| `alive_aod_restore_set` | 是否已 capture |
| `alive_aod_active` | UI 进程快速判断“我们是否活跃”的标记 |

### 8.2 `enter`

```java
static void enter(Context context) {
    int original = getInt(context, KEY_MODE, UNSET);
    if (original > 1) original = 1;
    if (getInt(context, KEY_HAS_RESTORE, 0) != 1) {
        if (original == UNSET) putString(context, KEY_RESTORE, null);
        else putInt(context, KEY_RESTORE, original);
        putInt(context, KEY_HAS_RESTORE, 1);
    }
    putInt(context, KEY_MODE, 1);
    putInt(context, KEY_ACTIVE, 1);
}
```

### 8.3 `restoreWhenForeign`

不是“一次判空就恢复”，而是：

- 每 1s 检查一次；
- 连续 5 次“不是我们的”才 restore；
- 如果中途又看到我们的壁纸，取消恢复。

这解决“装包/重启/WMS 重绑壁纸的空窗”导致误 restore。

### 8.4 `restore`

```java
if (getInt(context, KEY_HAS_RESTORE, 0) != 1) return;
int original = getInt(context, KEY_RESTORE, UNSET);
if (original == UNSET) putString(context, KEY_MODE, null);
else putInt(context, KEY_MODE, original);
putString(context, KEY_RESTORE, null);
putString(context, KEY_HAS_RESTORE, null);
putString(context, KEY_ACTIVE, null);
```

### 8.5 当前未解决问题

系统壁纸 ↔ 项目壁纸互切后，AOD 模式有时不恢复/恢复错值。见 `03-*` Bug C。核心怀疑：

- `AodFullScreen.onActivation` 与 `AodWallpaperMode.restoreWhenForeign` 的时序竞争；
- `ensureEnabled` 在 capture 标记不存在时调用 `enter`（**注意：`ensureEnabled` 开头就有 `if (!alive(context)) return;`，所以只有在“壁纸确实是我们的”前提下才会补写 marker，不会把系统壁纸当成首次应用——旧文本这里的因果写错了**，见 `AodWallpaperMode.java:304-322`）；
- system_server 与 UI 进程读到的 `doze_always_on`/壁纸状态不一致；
- 系统壁纸是静态壁纸，`getWallpaperInfo()==null`，但 `KEY_ACTIVE` 仍旧（这条成立：`uiAlive` 只在 `getWallpaperId(FLAG_SYSTEM) < 0` 时才回退到 marker，见 `AodWallpaperMode.java:71-90`）。

## 9. AOD 关闭守卫

用户关闭“息屏显示”后，预期：

- 不再注入 AodSurface；
- 不出现球；
- `full_screen_aod_on` 不被写回 1。

代码路径：

- `HyperOsAod.attach` 首行 `if (!aodEnabled(context)) { detach(); return; }`
- `AodFullScreen.hookAliveTrue` 要求 `aodEnabled`
- `AodFullScreen.onActivation` AOD-off 分支 restore 并 `restoreDoze`
- `AodWallpaperMode.enter/ensureEnabled` 都检查 `aodEnabled` + `aodSwitchFromShell`

b1c 实测：`doze_always_on=0` + `SceneApply` → `full_screen_aod_on=0`；真实电源键截图全黑；亮屏后 0。

## 11. 动画/转场

### 11.1 期望

- 桌面/锁屏 → 息屏：壁纸缩小/压暗成球，时钟淡入；
- 息屏 → 锁屏：球展开回壁纸；
- 不能瞬间黑屏/跳变。

### 11.2 相关代码

- `CleanWallpaper` 接收 `android.wallpaper.goingtosleep`，在真正灭屏前发 `mode(0)` 过渡；
- `RenderLoop` 用 `SceneMotion`/`NativeScene` 的 `v0` 控制球体进度；
- `HyperOsAod` 在 950ms 后注入 surface，首帧后 180ms alpha 淡入；
- `AodFullScreen.hookDoze` 在 `onDreamingStarted` 前强 `mFullAodEnable`，让 MIUI 走全屏 AOD 转场；
- `AodTransitionWindow` 已删除（旧实现）；当前依赖 MIUI 原生转场 + 我们的 surface。

### 11.3 当前证据

- `.tmp/screenshots/anim_b1c_home.mp4` / `anim_final.mp4`：转场帧有球；
- 用户反馈：稳定息屏没有球；系统动画变成缓慢黑屏，壁纸跟着变暗消失；
- 两者可同时成立：转场帧有球，稳定后 surface 被移除/alpha 0/纹理黑。

### 11.4 可能的动画链问题

1. `AodFullScreen.hookDoze` 强开 full AOD，改变 MIUI 原生转场；
2. `AodSurface` 在 950ms 才注入，晚于原生 896ms 转场，导致转场后半段才出现/或错过；
3. `AodSurface` 不透明黑底覆盖原生 AOD wallpaper，造成“壁纸变暗”；
4. `CleanWallpaper` 的 `goingtosleep` 与 native `FullAodAlphaShow` 同时驱动，两个进度竞争；
5. MIUI AODView 重建，surface 被移除，没有 supervise 重挂。

具体排查见 `03-*` Bug A 的决策树。
