## 3. 哪个版本“正常”？

这个问题必须按功能拆开回答：

### 3.1 动画/打断

**已知较好：`stable-anim-2026-11-02`。**

- 证据：HANDOVER 记录该 tag 是动画/打断表现最佳版本；
- 限制：它不能证明“稳定 AOD 有球”，也不能证明 b1c 的 AOD 关闭/个性化修复仍存在；
- 若当前动画明显退化，可 diff：

```bash
git diff stable-anim-2026-11-02..HEAD -- \
  app/java/org/aliveclean/CleanWallpaper.java \
  app/java/org/aliveclean/HyperOsAod.java \
  app/java/org/aliveclean/AodFullScreen.java \
  app/java/org/aliveclean/RenderLoop.java
```

### 3.2 AOD 关闭（关闭“息屏显示”后不出球）

**b1c 已验证 PASS。**

- `doze_always_on=0` + `SceneApply` → `full_screen_aod_on=0`；
- 真实电源键息屏截图全黑；
- 日志 `scene AOD skipped` / `overlay skipped`；
- 但这是“关闭”路径，不是“稳定球”路径。
- **2026-11-15 22:40 复核**：截图证据成立（`.tmp/screenshots/b1c_aod_off.png` 纯黑，18,223 bytes）；上面那几条日志在 `.tmp` 中**已找不到**（无 16:0x 之后的模块日志），只有 08a0 时期的同类日志。所以准确说法是“**截图已验证 + 日志证据缺失**”。

### 3.3 系统个性化缩略图

**b1c 已验证未复现灰白。**

## 5. 版本回滚建议

### 5.1 动画退化

1. 先备份当前 APK/源码；
2. 回滚到 `stable-anim-2026-11-02` 的 APK（如果 `.tmp/artifacts` 有）；
3. 复现同一动画场景；
4. 若旧版正常，二分 `CleanWallpaper/HyperOsAod/AodFullScreen/RenderLoop` 的 diff；
5. 不要把“旧版动画正常”当成“旧版 AOD 球正常”。

### 5.2 AOD 关闭失效

- b1c 已通过；若新构建回归，优先查 `AodWallpaperMode.enter/ensureEnabled`、`AodFullScreen.onActivation`、`SceneApply` 的 shell guard；
- 重启 system_server（整机）后再测。

### 5.3 缩略图灰白回归

- 优先查 `AodWallpaperPreview` 的 `original==null` 分支、`t8r` 字段写回、ThemeManager 是否重启；
- 回滚不是第一选择，先确认 hook 是否加载。

### 5.4 稳定球消失

- 目前没有确认正常版本；不要盲目回滚；
- 先补稳态证据，再决定是否回滚到 5f41/0ecc 对照；
- 重点查 `HyperOsAod.supervise` 未调用、surface 被移除、alpha 0、纹理黑。
