## 1. 场景模型：`scene` 键

### 1.1 存在哪里

- `SceneOptions.APPLIED = "scene"`、`SceneOptions.DRAFT = "scene.preview"`（`app/java/org/aliveclean/SceneOptions.java:6`）。
  即 SharedPreferences 文件 `shared_prefs/scene.xml` 与 `shared_prefs/scene.preview.xml`。
- **`scene` = 已经应用到系统壁纸的那份**；**`scene.preview` = 编辑器/预览的草稿**。
- `RenderLoop` 构造时用名字区分：`preview=SceneOptions.DRAFT.equals(name)`（`RenderLoop.java:85`）。
  `preview=true` 时它**不读 provider**（`loadPhoto` 只在 `primary && !preview` 才走 provider，见 §6.3）、也不接受 `backdrop` 事件；注意这与 `CleanWallpaper.isPreview()`（壁纸引擎是否处于系统预览）是两件不同的事，后者决定要不要注册 `SceneChannel`（`CleanWallpaper.java:92-95`）。

归一化是"硬钳制"，读代码即可确认（`SceneOptions.java:28-30`）：

```java
// app/java/org/aliveclean/SceneOptions.java:28-30
aod=cosmic!=0?0:a==-1||a==0||PhotoStyle.supported(a)||a==101?a:0;
lock=l>=0&&l<=5?l:2;
```

要记住的 4 条后果：

1. **只要 `cosmic!=0`，`aod` 一律变 0**（Cosmic 自己管 AOD 画面）。
2. `aod` 只认 `-1/0/1..5/101`，其它值（含 `6`、`100`、`102`）静默归 0。
3. `lock` 越界回落 2、`home` 越界回落 6，所以"设了 7 却像 6"要先看是否写过 `home=7`。
4. 文件名只允许 `[A-Za-z0-9._-]+` 且不能是 `.`/`..`（防路径穿越），非法就退回 `photo`。

## 3. mode 语义

### 3.1 0 / 1 / 2

| mode | 含义 | 谁来发 | 关键后果 |
|---|---|---|---|
| 0 | AOD（息屏） | `CleanWallpaper.send(0,…)`（灭屏广播 / `goingtosleep` / `action_alive_aod` / Surface 重建时 `panelDark`） | `pacer.doze(true)`、`aodMotion.enter()`、Cosmic 用 `cosmicContinuousAod`、`readWallpaperPalette()` |
| 1 | 锁屏 | `update()` 判定"锁屏仍锁着、且不在锁屏宽限期" → `send(1,…)`；`action_alive_lock` 也会触发 `update()` | 常态；构造函数里 `SceneMotion.values[1]=1` |
| 2 | 桌面（解锁后） | `action_alive_launcher` / `keyguard_going_away` / `keyguardHiding()` | `homeAt` 记时（`HOME_GRACE=1500ms`） |

`RenderLoop.mode(...)` 是唯一入口（`RenderLoop.java:174-183`），核心一行：

```java
// app/java/org/aliveclean/RenderLoop.java:181-182（节选）
int previous=mode;boolean visible=renderingVisible();
mode=next;pacer.doze(next==0);…if(previous!=next)AliveLog.i("AliveClean","scene motion "+previous+"->"+next+" animate="+animate+" visible="+visible+" pending="+motion.pending());
```

native 路径下 mode 直接变成"三层权重"的初值（`app/java/org/aliveclean/SceneMotion.java:63`，`values[0..2]` 分别是 aod/lock/home 的混合比）。

### 3.2 Cosmic 的三套调色板

`CosmicMotion` 一次读入三套 palette，`mode` 就是索引（`app/java/org/aliveclean/CosmicMotion.java:38-39`）：

```java
// app/java/org/aliveclean/CosmicMotion.java:38-39
String[] names={"aod","keyguard","unlock"};
float[][] geometry={{0,.325f,.22f,1,1},{.764f,-.206f,1.181f,.8f,.8f},{0,0,1.55f,.6f,1}};
```

`geometry` 的 5 个数按代码用法落位是 **`x / y / scale / 旋转速度 / 噪声幅度`**：
`values[0..1]` 当平移（`CosmicRenderer.java:101`）、`values[2]` 当缩放（`:102`）、`values[3]` 乘进角速度（`CosmicMotion.java:141`：`angle=(angle+delta*30*values[3])%360`）、`values[4]` 当 `u_noise_amplitude`（`CosmicRenderer.java:103`）。
三套的差别肉眼可见：
`aod` 是"原点上、缩放 0.22 → 小黑球"，`keyguard` 是"偏右下（y=-0.206）、缩放 1.181"，`unlock` 是"居中、缩放 1.55、转得更慢（0.6）"。

每套 palette 从 `assets/cosmic/v<variant>[_dark].json` 的 `aod / keyguard / unlock` 三个对象里取（`CosmicMotion.java:37-59`）：

- 5 个因子：`stripeDivergent / stripeThickness / highlightThickness / highlightStrength / alpha`；
- 5 个颜色：`baseColor / stripeColor1..3 / highlightColor`；
- 4 组渐变：`rotate_0 / rotate_90 / rotate_180 / rotate_270` 的 `startColor`+`endColor`；
- phoenix（101–105）额外取 7 个噪声参数、4 个 flow 颜色、6 个因子、`cameraPos[3]` + `cameraZoom`（`CosmicMotion.java:51-59`）。

`cosmic_keep_lock` 会把"桌面"改写成"锁屏"调色板：

```java
// app/java/org/aliveclean/CosmicMotion.java:63
mode=keepLock&&scene==2?1:scene;System.arraycopy(states[mode],0,values,0,SIZE);
// app/java/org/aliveclean/CosmicMotion.java:78
if(keepLock&&next==2)next=1;
```

### 3.3 2026-11-16 的回归与修复（palette=mode）

**现象**：主页三张卡片里「息屏」和「锁屏」是同一张画面；编辑页 `scene=0` 也是整屏壁纸，而真机息屏是"黑底 + 顶部一个球 + 时钟"。

**根因**（回归由 `85cfa94` 引入）：把 mode 0 强行映射到 keyguard 调色板。

当前代码（已修）与注释：

```java
// app/java/org/aliveclean/RenderLoop.java:261-269
if(options.cosmic!=0){
    boolean dark=(context.getResources().getConfiguration().uiMode&android.content.res.Configuration.UI_MODE_NIGHT_MASK)==android.content.res.Configuration.UI_MODE_NIGHT_YES;

    // CosmicMotion ships three palettes (aod/keyguard/unlock); the aod one draws the
    // wallpaper as a small sphere on black, which is exactly what the always-on screen
    // shows. Forcing the keyguard palette here (85cfa94) made every AOD preview -- the
    // home cards and the editor's 息屏 page -- render the lock screen instead of the ball.
    int palette=mode;
```

修复内容就一行（旧形态见 `troubleshooting/02-已定位Bug档案.md` §12.9 的记录：`int palette = mode==0 ? 1 : mode;  // 85cfa94 引入`）：

```diff
- int palette = mode==0 ? 1 : mode;
+ int palette = mode;
```

**证据**：

- 【实测】截图差分：三张卡片裁切后 `aod vs lock` 平均差 **4.17**，`aod vs home` **14.74** —— 息屏与锁屏几乎逐像素相同（`troubleshooting/02-已定位Bug档案.md` §12.9）。
- 【实测】真机息屏实拍（`input keyevent 26` → `STATE_DOZE` → `screencap`）：黑底 + 椭圆球 + 时钟。
- 【支持】装机 `f2630bc`（2026-11-16 18:00）后用户确认"正常"，主页/编辑页息屏预览恢复为黑底+球（`history/01-版本与回归历史.md`）。
- 修复后的行为差异点：`CosmicMotion` 的 aod 几何 `{0,.325f,.22f,…}` 就是"缩到 0.22 的小球"，这是"预览要显示球"的判据。

### 3.4 native 路径下"息屏为什么是球"

native 场景没有 palette，球来自 `SceneMotion` 的 lens 参数 + `aod` 参数：`mode==0` 时 `values[FULL]=values[FULL+1]=1`（`FULL=21`，`SceneMotion.java:68`）、lens 的 `scale/zoom/ripple` 由 `lensState(0)` 给出（`SceneMotion.java:85-88`），native 的 `aod_pass` 用它们做"模糊底图 + 透镜球 + 涟漪"（`native/renderer.rs:116-158`）。

## 4. 转场：SceneMotion

### 4.1 `tr0..tr5` 是什么

`tr` 不是 mode，而是"从哪到哪"的编号（`app/java/org/aliveclean/SceneMotion.java:94-97`）：

```java
// app/java/org/aliveclean/SceneMotion.java:94-97
static int transition(int from,int to) {
    if(from==0)return to==1?0:2;
    if(to==0)return from==1?1:3;
    return from==1?4:5;
}
```

| tr | from → to | 读数 |
|---|---|---|
| 0 | 0(AOD) → 1(锁屏) | "球展开成锁屏" |
| 1 | 1(锁屏) → 0(AOD) | "锁屏收成球" |
| 2 | 0(AOD) → 2(桌面) | "球展开成桌面" |
| 3 | 2(桌面) → 0(AOD) | "桌面收成球" |
| 4 | 1(锁屏) → 2(桌面) | 解锁 |
| 5 | 2(桌面) → 1(锁屏) | 锁屏 |

有一处覆盖：`aod==0 && previous==0 && next==2` 时强制 `tr=0`，并打 `scene sail lock animation 0->2 tr=0`（`SceneMotion.java:191`）。

### 4.2 各 tr 的时长与曲线（lens / glass / ground / full）

`lens()` 给 10 个 lens 槽位分别定时长和曲线（`SceneMotion.java:106-143`）：

| tr | 主要时长 | 曲线 | 备注 |
|---|---|---|---|
| 0 / 2 | `ms[0]=183`、`ms[3]=33`，其余 `800..1000` | `EASE`（`path(.33,0,.67,1)`）、`EXPAND`（`path(.13,.04,0,1)`）、`DISTORT` | `ms[9]=24` + `ROTATE` 做整体旋转；`tr==0` 才用 `EXPAND` |
| 1 / 3 | 前 8 个统一 `650` | `curves[0]=path(.17,0,.83,1)`、`curves[4]=path(.37,.02f,.04,1)`、`COLLAPSE` | `rippleDelay=650`（涟漪第二轮），`ms[8]=0` |
| 4 | `ms[0]=3840`、`ms[1,5,6]=650`、`ms[2]=600` | `EASE` / `EXPAND` / `DISTORT` | 锁屏→桌面，玻璃展开最慢 |
| 5 | `ms[0]=0` | `EASE` | 桌面→锁屏：瞬时到位 |

`glass()`（`lock==1||2` 时才跑）与 `ground()`（`lock==3`）：

- `tr0/tr5`：`i==3 ? (tr==0&&lock==2 ? 470 : 425) : 850`，曲线 `path(.23,.09,.16,1)`；
- `tr2`（AOD→桌面）：统一 `200ms`（这就是"桌面层很快接上"的原因）；
- `tr3`：`i==0 ? 800 : 200`；
- `tr1/tr4`：`i<4 ? 1500 : 700`；
- `ground`：`tr0/tr5 ? 1500 : 200`，`LINEAR`，并在 `tr1/tr4` 置 `groundMask`（换一次随机偏移）。

`full()`（`aod==101` 全屏 AOD）只在 `tr<=3` 生效：`tr0→250`、`tr1→1300`（曲线 `path(.19,1.91f,.47f,1.02f)`，带回弹）、`tr2→250`、`tr3→800`。

### 4.3 三层混合：`blendDuration` 与 `blendCurve`

`values[0..2]` = (aod, lock, home) 权重。混合时长按 tr 从三张表里取 max（`SceneMotion.java:175-182`）：

```java

    long[] a=aod==0?new long[]{950,650,300,650,650,300}:
            aod==101?new long[]{250,1200,350,350,300,300}:new long[]{400,400,400,400,400,400};
    long[] l=lock==0?new long[]{250,250,250,250,400,400}:
            lock>=4?new long[]{250,250,250,250,500,500}:
            lock==3?new long[]{1500,200,200,200,200,1500}:new long[]{850,200,200,200,500,850};
```

### 5.2 attach / redraw：重试与代际


### 5.3 schedule + 120ms vsync 看门狗

```java
// app/java/org/aliveclean/RenderLoop.java:215-231
private void schedule(){
    if(!((renderingVisible()||forceFrame)&&(scene!=0||cosmic!=null||vivo!=null)))return;
    if(choreographer!=null&&!framePosted){framePosted=true;choreographer.postFrameCallback(frame);}
    // Choreographer 在 doze/息屏期间可能整段不发 vsync；一旦回调不来，framePosted 会
    // 永久卡在 true，之后 schedule() 全是空操作 —— 表现就是"surface 在、画面永远不出"。
    // 这里兜一个 120ms 的看门狗：只在 vsync 真的没来时直接渲染一帧。
    handler.removeCallbacks(vsyncWatchdog);
    handler.postDelayed(vsyncWatchdog,120);
}
private final Runnable vsyncWatchdog=()->{
    if(!framePosted)return;
    framePosted=false;
    if(!(renderingVisible()||forceFrame)||(scene==0&&cosmic==null&&vivo==null))return;
    AliveLog.i("AliveClean","vsync watchdog: drawing without Choreographer mode="+mode);
    try{frameTime=android.os.SystemClock.uptimeMillis()*1_000_000L;render(frameTime);}
    catch(Throwable error){AliveLog.w("AliveClean","vsync watchdog render failed",error);}
};
```

这条看门狗是 `1095efd`（2026-11-15 23:50）为"息屏首帧永不出"引入的，装机后 `cycle1..6` 均有球（`history/01`）。
看到 `vsync watchdog: drawing without Choreographer` **不是错误**，而是"这次是看门狗救的帧"。

### 5.4 帧节流：`VsyncPacer` 现在 LIVE 与 DOZE 都是 8ms

`app/java/org/aliveclean/VsyncPacer.java:4-5`：`LIVE_INTERVAL_NS = DOZE_INTERVAL_NS = 8_000_000L`。
也就是说代码层面 AOD 并没有被降到 1fps 之类；**AOD 省电靠的是"动完就停"**（`moving` 为假时不再 `schedule()`），不是降帧率。

### 5.5 doze 期间的三个时间窗

| 窗口 | 值 | 代码 | 作用 |
|---|---|---|---|
| `AodMotionWindow` | 3000ms | `app/java/org/aliveclean/AodMotionWindow.java` | `mode(0)` 后 3s 内 `speed` 从 1 线性降到 0，之后 `running=false` → 静态 |

### 5.6 可见性与 backdrop 门控

```java
// app/java/org/aliveclean/RenderLoop.java:184-186
```

- `visible`：壁纸是否真的可见（`CleanWallpaper.refreshVisibility()` 按 display state 判定）；
- `backdrop`：SystemUI 的下拉/通知栏是否盖住（`scene backdrop` 通道，`SceneChannel` what=3）；
- 任一为假 → `renderingVisible()==false` → `schedule()` 直接 return，且 `render()` 首行也会早退。

### 5.7 首帧回调

`swap()` 里第一次 `eglSwapBuffers` 成功后才回调一次 `firstFrame`（`RenderLoop.java:437-447`）。
使用者是 `HyperOsAod.AodSurface`：`loop.onFirstFrame(...)` 之后才把 surface alpha 0→1（`FADE_MS=180`，`HyperOsAod.java:20,435-439`）。**首帧不来 = 永远透明 = 用户只看到系统时钟**（这是 AOD"稳定无球"的核心机理，见 `troubleshooting/02` Bug A）。

### 5.8 release 顺序

`release()`（`RenderLoop.java:448`）顺序：`stopFrames()` → `vivo.close()` → `closeCosmic()`（含 `StereoSensor`）→ `closeFrame()` → `motion.close()` → `NativeScene.destroy` → 删纹理 → `eglMakeCurrent(NO_SURFACE)` → `eglDestroySurface/Context` → `eglTerminate/ReleaseThread`。
漏掉其中任何一步的典型症状是"重建后黑屏/纹理错乱"。

### 5.9 时钟帧回执

`mode==1` 且需要时钟帧时，`clockTransition(token)` 记录 token，渲染提交后 `SceneChannel.frameReady(token, submitted)` 回给 SystemUI（`RenderLoop.java:157-160`，`SceneChannel.frameReady`）。这是"锁屏时钟与壁纸帧对齐"的通道，与画面内容无关。

### 7.2 EGL init 日志怎么读

`EGL init requested=1200x2608 eglSurface=1200x2608 valid=true`：

- `requested` 是 `onSurfaceChanged` 给的尺寸；`eglSurface` 是 `eglQuerySurface` 实测到的真实尺寸。
  **两者长期不一致 = 系统给的 buffer 尺寸被改过**（缩放/裁剪问题的源头）。
- 行尾的 `valid=` 是当时的 `surface.isValid()`，正常恒 `true`（`attach`/`redraw` 会先拦无效 surface，走不到 `init`）。若这里出现 `false`，说明 surface 在 `attach` 与 `init` 之间失效了 —— 紧跟的必然是 `attach retry` 或 `Renderer initialization failed`。
- `eglSurface` 尺寸为 `0x0` → 系统还没给出 buffer，这次一定会失败重来。
- 完全没有这行 → 没走到 `init()`：先查 `attach`/`redraw` 日志与 `surfaceGeneration`（stale 会打 `attach stale generation`）。

### 7.3 `scene motion X->Y` 怎么用

- 有这条但画面不动 → 看 `visible`/`pending`：`pending=true` 表示在等 `visible`（`updateRenderActivity()` 才会 `startPending()`）；
- 完全没有这条 → 说明 `mode(next)` 里 `previous==next`，或 `CleanWallpaper` 根本没下发（查 `scene send`/`scene reconcile`）；
- `X->Y` 与实际相反 → 查 `CleanWallpaper.update()` 的 `lockGraceActive`（亮屏宽限，最长按 `FINGERPRINT_WINDOW=900ms` 拖）与 `HOME_GRACE=1500ms`（`CleanWallpaper.java:21`）。【推断】这两处是最可能把 1/2 判反的地方，未在设备上单独验证。

| 黑屏 | `scene==0 && cosmic==null && vivo==null` 时 `schedule()` 与 `render()` 都直接 return；或 `init()` 抛异常后 `release()` | `Renderer initialization failed`、`attach skipped`、`GLES3 scene ready`（需 TRACE） |
| 画面不变 | `moving=false` 时只画一帧；`renderingVisible()==false` | `visible`/`backdrop` 状态、`scene reconcile … (unchanged)` 一次性日志 |
| 双层（AOD 层盖桌面） | 三层 `ratio` 交叉淡入过长（§4.4），锁屏带纹理时最明显 | 打一版 `wake t=… ratio=…` 诊断日志（`044f0c1` 的做法），确认 `ratio[0]` 何时归零 |
| 卡住（surface 在但不出帧） | Choreographer 在 doze 不发 vsync，`framePosted` 永久 true | 有没有 `vsync watchdog`；没有的话说明 `schedule()` 根本没被调用 |
| 息屏预览显示成锁屏 | Cosmic palette 用错（§3.3） | `CosmicMotion` 的 `geometry[0]` 是否是小球（缩放 0.22） |
| Vivo 场景起不来 | `VivoEngineRuntime.prepare` 20s 超时 → `IOException("Vivo engine initialization failed")` | `Renderer initialization failed` 的 cause |

## 附：启航（sail）的唤醒转场规则（2026-11-16 定版）

**识别**：`sail = (cosmic==0 && aod==0)`，`RenderLoop.sail` / `sailScene()`。

**三条硬规则**

1. **两条路径各自独立，但参数共用**：锁屏(1) 与桌面(2) 都必须渲染自己的构图——
   2026-11-16 曾试过"启航不渲染桌面构图"（`send()` 拦掉 mode 2），结果**锁屏纹理被带到桌面**，已回退。
   正确的做法是让两条转场的参数同源（见下面第 2 条），而不是砍掉一条路径。
2. **模糊是转场瞬态，不是稳态参数**：`lensState()` 是**动画结束后的目标值**，
   启航的锁屏构图取样自 AOD 层（blend 用 `u_aod_effect`，`aod_pass` 做 `blur(lens[0])`），
   所以 `lensState(1)[0]` 必须是 0；转场期间的模糊来自 `values[LENS+0]` 从 22 衰减到 0，
   时长 `ms[0]`（`tr==0` 分支）约 650ms。
3. **验证方式**：`SceneMotion.change()` 每次转场打一行
   `scene transition 从->到 tr=… lensTarget=… glass=…`；两条路径应逐字相同。
   2026-11-16 21:57 实测：`0->1 tr=0 lensTarget=0.0,1.24,0.0,0.0 glass=1.0` 与
   `0->2 tr=0 lensTarget=0.0,1.24,0.0,0.0 glass=1.0` 一致。

**调试注意**：`RenderLoop` 的 `probeUntil` 过期后必须清零，否则每帧写一行日志把现场冲掉。
