### 2.1 标准命令


### 2.2.1 验证“这个 APK 到底是不是这份源码构建的”（2026-11-15 新增，实测有效）

只看 SHA 只能证明“是不是同一个文件”，不能证明“是不是这份源码”。低成本做法是**在 dex 里搜源码独有的日志串**：

```python
# .jxai/tmp 下跑，别污染仓库
import zipfile
apk = r"dist/AliveHS-0.1.0-arm64-v8a.apk"
needles = ["aod mode enter skipped: AOD is disabled",
           "aod restore cancelled: wallpaper is still ours",
           "scene re-attached after misses",
           "inner AODView not up yet, waiting",
           "full aod hooks="]
with zipfile.ZipFile(apk) as z:
    blobs = {n: z.read(n) for n in ("classes.dex", "classes2.dex") if n in z.namelist()}
for s in needles:
    print("FOUND" if any(s.encode() in b for b in blobs.values()) else "MISSING", s)
```

- 全部 `FOUND` → 产物包含当前源码的改动；
- 有 `MISSING` → 产物是旧的/半包，**先重构建再测**。

> 这不是多余步骤：2026-11-15 上午的 `08a0` 构建就发生过“SHA 与报告一致、但 APK 内根本没有 `aodEnabled` 守卫”的事故（`.tmp/aod-evidence/report.md` §2.3）。2026-11-15 22:40 用上述方法复核 b1c，5 个串全部命中，判定 b1c 与当前工作区源码一致。

### 2.2.2 构建前的检查脚本（2026-11-16 重做）

`tools/build_release.py` 的 `CHECKS` 改成**自动发现** `tools/check_*.py`。以前硬编码 9 个名字，

### 2.3 常见构建错误

| 错误 | 原因 | 处理 |
|---|---|---|
| `check_layout.py` 引用了不存在的类 | 检查器过期 | 用 `--no-checks`；修检查器 |
| `sources2.txt` 找不到新类 | 源码列表没更新 | 重新生成/更新 sources2 |
| `javac` 报 `cannot find symbol` | 新类没进 sources2，或 API stub 不匹配 | 查 `sources2.txt`、`android.jar` |
| D8 报 duplicate class | 依赖重复/旧 class | 清 `.tmp/build`、检查 assets/libs |
| `apksigner` 失败 | keystore/密码/路径 | 查构建脚本签名配置 |
| APK 体积异常 | assets 未打包/重复 | 对比 308MB 基线 |

## 4. 重新应用项目壁纸

安装/重启后，系统壁纸可能回退到 MIUI `ImageWallpaper`，`full_screen_aod_on` 可能变 0。先解锁，再执行：

```bash
# 取设备上的 APK 路径
APK_PATH=$("$ADB" -s $D shell pm path org.aliveclean | sed 's/package://' | tr -d '\r')
echo "$APK_PATH"

"$ADB" -s $D shell su 1000 -c \
  "CLASSPATH='$APK_PATH' /system/bin/app_process /system/bin org.aliveclean.SceneApply"
```

预期：

```text
SCENE_APPLIED
```

检查：

```bash
"$ADB" -s $D shell dumpsys wallpaper | head -40
"$ADB" -s $D shell settings get secure doze_always_on
"$ADB" -s $D shell settings get secure full_screen_aod_on
```

预期：

- system 壁纸组件 = `org.aliveclean/.CleanWallpaper`；
- `doze_always_on=1`；
- `full_screen_aod_on=1`。

若失败：

- 含 `AMBIENT_WALLPAPER` → 勾 `system` 作用域 + 重启；
- 输出里出现 Settings/ContentProvider 异常或直接超时 → 先解锁再重试（**别再等 `RUNNING_LOCKED` 这个串，源码里没有**，见 `../troubleshooting/03-作用域与权限排错.md` §3.2）；
- 超时 → root 授权/子进程卡住；
- 成功但壁纸没变 → 查 `dumpsys wallpaper`、锁屏槽、多用户。
