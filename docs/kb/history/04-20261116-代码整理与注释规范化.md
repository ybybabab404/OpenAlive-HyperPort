## 1. 结论先说

- **像素输出未变**：每个阶段都用 `tools/compare_apks.py` 对基线 `1f071d5.apk` 做结构比对，
  除下面 §3 逐条登记的 11 项删除外，**没有新增或缺失任何类/成员**；构建哈希的差异只来自注释改变行号表。
- **可上传/可在别处构建**：`python3 tools/build_release.py`（不带 `--no-checks`，即 CI 命令）在干净克隆里从零跑通。
- **注释可信**：136 个 Java 类全部有类注释，并且经过 5 轮"注释 ↔ 代码"交叉审核，累计改正 **50 余处**
  与代码不符的说法（清单见 §4）。

## 2. 让仓库像个正常 GitHub 项目

| 问题 | 处理 |
|---|---|
| `CHECKS` 硬编码 9 个脚本，其中 7 个文件早已不存在 → 任何带检查的构建必失败 | 改为按文件名自动发现 `tools/check_*.py` |

| 无工具能发现"删了类但 Manifest/脚本还引用" | 新增 `check_imports.py`（Manifest 组件类 + 检查脚本可编译 + vendor 输入校验） |
| 文档里全是本机绝对路径 | `docs/port/*`、`facts/01`、`ai/01` 脱敏为 `<repo>/<sdk>/<jdk>/<ndk>` |
| 无法证明"重构没改行为" | 新增 `tools/compare_apks.py`（zip 条目 + dex 类/成员清单对照） |

## 4. 交叉审核抓到的 50 余处"注释说的和做的不一样"

分五轮，每轮都派独立子代理只读审核，我逐条复核（不采信结论，必读代码确认）后再改。

代表性错误（详见各轮提交信息）：

| 类型 | 例子 |
|---|---|
| 指错文件 | `NativeScene` 的 JNI 写成 `lib.rs`（实际 `renderer.rs`）；`GradientRenderer` 把顶点着色器的结构体说成在 `.frag` |
| 说错结构/方向 | `AodSettingsGuard` 说"追加三项"（实际原地替换 index 1）；`KeyguardTouchRelay` 说"转发给目标 View"（实际跨进程发给壁纸渲染器）；`VivoTextureLayer` 说"把参数交给引擎"（方向相反，是回给厂商）；`ModuleActivationProvider` 说"供系统侧查询"（系统侧是上报方） |
| 说错行为 | `PhotoDecode` 承诺"最后精确缩放"（代码明确不做）；`DeviceIdleDelayHook` 承诺推迟 1.2s（arm/cancel 条件相同，实际不生效）；`ClockUpdates` 说"预览没广播所以自己触发"（广播照旧注册） |
| 说错返回值/维度 | `ThemeLinks`"失败返回 false"（返回 Intent/null）；`SceneMatrices`"3×3"（4×4） |
| 指向已删机制 | 三份文档还在教人看已删除的 `probe draw` 日志；`Diagnostics` 引用不存在的 `docs/kb/05` |
| 死代码当活代码写 | `AodClockView` 说"注入系统 AODView"（只被预览用）；`VivoGlyphDistanceField` 说"给引擎着色器用"（生产零引用） |

## 5. 发现但**没修**的代码缺陷（`../troubleshooting/02-已定位Bug档案.md` §13）

修它们都会改变行为，按用户"克制"的要求只登记：

1. **§13.1** `RootBridge` 读 `PlatformApply` 从不输出的 `backgroundAllowed` → 非 HyperOS 路径每次弹假告警；
2. **§13.2** `WallpaperPicker.applied()` 的 4 个参数只进日志、不参与判定；
3. **§13.3** `PlatformApply` 的 `local-aod` 参数无调用方；
4. **§13.4** 9 处 `setReadOnly()` 先于写入（靠已打开的 FD 才成功，顺序脆弱）；
5. **§13.5** `DeviceIdleDelayHook` 的 arm/cancel 条件相同 → 推迟从不发生。

另有两个"零引用但不像垃圾"的候选，等用户决定：`VivoGlyphDistanceField`（3.8 KB 距离场算法）、
`AodClockView.tick()` / `notificationTop()`（抽象契约，目前无调用方）。
