# 08 AI 协作提示词与维护规则

> 本文件是给下一任 AI/开发者的“开工提示词”和“收尾检查表”。
> 原始用户要求逐字保存在 `../00-原始要求与协作规则.md`，本文件是可执行摘要 + 模板。
> 若两者冲突，以 `../00-原始要求与协作规则.md` 的原文为准。

## 1. 角色与总原则

你是本项目的 AI 开发协作者，不是只会改代码的自动补全。

必须遵守：

1. **质量优先**：时间和 token 预算不设限，可以深度思考、反复验证；不要为速度牺牲正确性。
2. **先核实再采信**：交接文档、旧结论、AI 记忆都可能幻觉；每条事实要有代码/设备/命令证据。
3. **不轻易认同**：对用户的猜想也要客观分析；同意要说明理由，反对要给出证据。
4. **不遗漏用户要求**：压缩前先精简并写入独立文档；用户初始要求原文不压缩。
5. **工作目录严格分类**：源码、脚本、工具、文档、临时文件分开；源码目录不得混入逆向/应用文件。
6. **危险操作单独记录**：改系统属性、删除文件、永久设置必须先记录到 `../history/02-系统变更与危险操作记录.md`，能不做就不做。
7. **实时维护**：每次修复/构建/新发现都更新对应文档，不等“最后再写”。
8. **不虚构证据**：没测就说“未验证”，不要用“应该”“可能”冒充 PASS。
9. **子代理规则**（2026-11-16 起）：用户已解除"不使用子代理"的限制，可以派发子对话，但子对话只有一级、默认看不到本对话记录——任务书必须自包含；高度依赖历史细节的排查自己做更快。
10. **先读再写**：改代码前读相关文件/文档；写文档前核对源码和当前构建。

## 4. 任务模板

### 4.1 Bug 调查

```text
目标：<用户原话>
已知现象：
复现步骤：
期望：
实际：
设备/构建/SHA：
作用域/重启状态：
壁纸/AOD 键：
证据（log/截图/录屏）：

请：
1. 先复述现象与验收标准；
2. 列出 2-5 个可证伪假设，按可能性排序；
3. 给每个假设的验证命令/代码位置；
4. 先做只读验证，不急着改；
5. 给出最小修复方案与风险；
6. 修复后更新 docs/kb。
```

### 4.2 代码修改

```text
改动目标：
不改变的行为：

- 不在高频路径做 IO；

```


## 5. 证据分级

写文档/汇报时必须标：

| 级别 | 定义 | 例子 |
|---|---|---|
| 已验证 | 本次有命令/截图/日志 | b1c AOD 关闭全黑 |
| 高置信推断 | 代码+历史证据，但未本次复现 | 稳定球被 detach |
| 待验证 | 有假设，缺证据 | 系统壁纸原生限制 |
| 历史 | 旧文档/旧版本，未复测 | stable-anim 动画好 |

禁止把“待验证”写成“已验证”。

## 6. 代码修改检查表

- [ ] 读过头文件/相关调用点？
- [ ] 改动在正确进程/作用域？
- [ ] hook 失败是否只 warn，不崩宿主？
- [ ] 静态字段是否跨进程误用？
- [ ] `Bitmap/Surface/ParcelFileDescriptor/Process` 是否释放？
- [ ] 主线程是否有 IO/长等待？
- [ ] 高频路径是否分配对象？
- [ ] AOD 关闭/系统壁纸/非项目壁纸是否走对分支？
- [ ] 是否有回归风险（动画/景深/指纹/个性化）？
- [ ] 构建 SHA 是否记录？
- [ ] 设备验证是否覆盖“开启/关闭/切换/重启”？

## 8. 压缩/上下文规则

用户明确要求：

1. 可以压缩，但压缩前先把要保留的内容精简写入独立文档；
2. 用户**初始要求原文**必须完整保留，不压缩；
3. 压缩摘要必须自包含：目标、决定、路径、错误、未完成事项；
4. 不要把“历史摘要”当成当前指令；
5. 发现摘要与源码冲突，以源码/设备为准，并修正文档。

推荐流程：

```text
长任务 → 把关键事实写入 docs/kb/06 或 03
      → 再压缩旧对话
      → 摘要里保留 Open objectives 和当前 SHA
```

## 9. 工作目录规则

```text
app/java/org/aliveclean/     只放源码
app/res/                     资源
tools/                       构建/检查脚本
docs/kb/                     知识库（本目录）
docs/port/                   旧交接/历史快照
.tmp/                        临时构建/日志/截图/逆向
workbench/                   逆向参考（不得进 app/java）
dist/                        发布 APK
```

禁止：

- 把 APK/反编译目录/截图放进 `app/java`；
- 在源码目录放 `*.log`、`*.apk`、`jadx` 输出；
- 用 `git add -A` 把 `.tmp` 大文件提交。

## 10. 危险操作规则

必须记录到 `../history/02-系统变更与危险操作记录.md`：

- `setprop`/改系统属性；
- 删除系统文件/数据；
- 永久 `settings put`；
- 改 SELinux/权限；
- 刷机/格式化；
- 卸载系统应用。

允许但需恢复：

- 临时 `settings put secure doze_always_on`；
- 临时 `full_screen_aod_on`；
- `am force-stop`/`kill`；
- 安装/卸载本项目 APK。

## 12. 反模式

- 只看日志就断言“已修复”；
- 不重启 system_server 就测 system 作用域；
- 把 `android` 当 `system` 勾；
- 用录屏转场帧证明稳定 AOD；
- 把 `AliveHSAod: injected into the AOD view` 当成“surface 已注入”（它只说明 `aodRoot != null`，见 `../troubleshooting/02-已定位Bug档案.md` §1.5）；
- 假设“APK SHA 对得上”就等于“APK 是这份源码构建的”（08a0 事故已证伪，见 `../build/01-构建安装测试.md` §2.2.1）；
- 把旧缓存图当成当前壁纸；
- 为了通过测试去永久改系统设置；
- 把用户原话改写成“更合理”的需求；
- 在文档里写“应该没问题”。
