# 05 个性化入口与缩略图

> 本文件讲三件事：
> 1. AliveHS 是怎么被塞进系统「桌面、壁纸和个性化」页的（插在哪、依赖哪些布局 id、失败什么表现）；
> 2. 我们自己的主页（`HomeActivity`）三张卡片（息屏/锁屏/桌面）的图到底从哪来；
> 3. 系统个性化页那两张缩略图（`AodWallpaperPreview`）hook 了什么、为什么以前是灰白。
>
> **行号基准：2026-11-16 工作区快照**（写作时逐条 grep 核对）。证据级别沿用 `../README.md` §2：**【实测】/【日志】/【支持】/【推断】/【证据不足】**。

相关文档：AOD 注入与样式锁定见 `features/02-息屏显示与AOD详解.md`；渲染与预览为何显示成锁屏见 `features/03-壁纸场景与渲染管线.md` §3.3。

## 1. 系统个性化入口（`PersonalizeEntry`）

### 1.1 宿主与挂载点

| 项 | 值 | 锚点 |
|---|---|---|
| 宿主包 | `com.android.thememanager` | `PersonalizeEntry.java:24`（`HOST_PKG`） |
| 宿主 Activity | `com.android.thememanager.settings.personalize.activity.PersonalizeActivity` | `PersonalizeEntry.java:25` |
| 跳转目标 | `org.aliveclean.HomeActivity` | `PersonalizeEntry.java:27` |

| 幂等标记 | `alivehs.personalize.card` | `PersonalizeEntry.java:29` |
| 注册点 | `CleanHooks.java:93`（`themeManager` 进程） | 同进程还有 `AodWallpaperPreview.installThemeManager`（`CleanHooks.java:94`） |

`install()` 只做两件事：找宿主类（找不到就 warn 后 return，不报错），hook `onResume` 的 **after**：

```java
// app/java/org/aliveclean/PersonalizeEntry.java:34-45（节选）
public static void install(ClassLoader cl) {
    Class<?> activityClass = Xp.findClassIfExists(ACTIVITY, cl);
    if (activityClass == null) {
        AliveLog.w(TAG, "personalize: " + ACTIVITY + " not found");
        return;
    }
    Xp.findAndHookMethod(activityClass, "onResume", new Xp.MethodHook() {
        @Override protected void afterHookedMethod(Xp.MethodHookParam param) {
            Activity activity = (Activity) param.thisObject;
            View decor = activity.getWindow() == null ? null : activity.getWindow().peekDecorView();
            if (decor == null) return;
            decor.post(() -> inject(activity, 0));
        }
    });
}
```

每次 `onResume` 都会再跑一次 `inject`，靠 tag 早退，不会重复插入。

### 1.3 失败会怎样（**纠正一条旧说法**）

- 找不到锚点、父容器不是 `ViewGroup`、或插入过程抛异常：**重试 12 次、每次 120ms（约 1.44s）**，之后静默放弃：

```java

    if (attempt < 12) retry(activity, attempt);
```

```java
// app/java/org/aliveclean/PersonalizeEntry.java:84-87（节选）
AliveLog.i(TAG, "personalize: entry injected");
} catch (Throwable t) {
    AliveLog.w(TAG, "personalize: inject failed", t);
    if (attempt < 12) retry(activity, attempt);
```

- **`PersonalizeEntry` 全程不调用 `SettingsScreen.fail`**。
  全仓 `SettingsScreen.fail` 只有两个调用点：`HomeActivity.onCreate` 的 catch（`HomeActivity.java:86`）与 `DynamicLibraryActivity`（`DynamicLibraryActivity.java:52`），它们弹"页面无法打开"对话框并 `finish`。
  所以两条失败路径的用户可见表现完全不同：

| 失败点 | 用户看到 | 日志 |
|---|---|---|
| 个性化入口注入失败 | 个性化页**照常显示**，只是没有 AliveHS 卡片（无弹窗） | `personalize: inject failed` / `personalize: … not found` |
| `HomeActivity` 构建页面失败 | 弹窗"页面无法打开" + 返回 | `Official settings UI failed`（`SettingsScreen.java` 的 `fail`） |

- 入口注入成功但缩略图错，是另一件事，见 §3。

| 卡片 | 有小米书包时 | 没有时 |
|---|---|---|
| 息屏（mode 0） | 静态缩略图 + `XiaomiHomePreview.Clock`（复用 `XiaomiAodPreview.Renderer` 画小米 AOD 时钟） | 自家 `RenderLoop` 走 `scene`（APPLIED）里的场景，`mode=0` |

### 2.3 `XiaomiHomePreview.load`：资源名与选包


| 卡 | 资源名 | 选哪个包 |
|---|---|---|
| 息屏 | `aod_small_preview` / `aod_small_preview_dark` | 锁屏包 `XiaomiState.selected(c,1)` |
| 锁屏 | `lockscreen_small_preview` / `lockscreen_small_preview_dark` | 锁屏包 `XiaomiState.selected(c,1)` |
| 桌面 | `home_small_preview_<land>` / `…_dark` | 桌面包 `XiaomiState.selected(c,2)` |

选包逻辑（`XiaomiHomePreview.java:28-40`）：`mode==2` 用桌面包，其余用锁屏包；包为 `null` → 该卡 `cards[mode]` 留 null（回退 RenderLoop）。
meta-data 来自 APK 里 `is_super_wallpaper=true` 的 service（`:17-20`）；名字为 0 时抛 `Original stage thumbnail missing`，解码失败抛 `Original stage thumbnail unreadable`，都被 catch 成 warn（卡片仍然可点，只是回退 RenderLoop）。

缩略图采样：`inSampleSize` 翻倍直到宽度 ≤640（`XiaomiHomePreview.java:44`），避免三张卡片各自解码全尺寸图。

### 2.4 线程与生命周期

- `onResume()`：自增 `previewLoad` token，起线程 `"HomeWallpaperPreviews"` 调 `XiaomiHomePreview.load(this)`，回主线程按 token 应用（`HomeActivity.java:107-113`）——token 防"退出后回调打到已销毁页面"。
- `onPause()`：`previewLoad++` 并 `preview.stop()`（`HomeActivity.java:115`），`stop()` 会 `releaseSurface()` 并关掉 `RenderLoop`（`HomeScenePreview.java:36`）。

### 3.2 返回什么图

图源链（`AodWallpaperPreview.java:264-320`）：

1. `content://miui.keyguard.editor.templatefileprovider/template_current/wallpaper_home`（`:264-274`，`decodeFileDescriptor`）；
2. `/data/user_de/0/com.miui.aod/files/templates/current/wallpaper_home`（`:14-15,313`）；
3. 同目录 `wallpaper`（`:314`）；
4. 都拿不到 → 返回 null，hook 不动原结果。

缓存键是 `lastModified*31 + length`（`:316-317`），文件改了自动失效。

尺寸处理：与原结果同尺寸就直接用，否则 `Bitmap.createScaledBitmap` 并回收临时图：

### 3.3 灰白占位：根因与修法

- **根因（两段）**：①旧版在 `original == null` 时直接 `return`，宿主拿不到 replacement，继续画自己的灰白占位；②个性化页的锁屏/桌面卡走的是 `LockScreenWpTool/DeskWpTool.toq`，而活壁纸在那里本来就没有静态 bitmap → 一定返回 null。
- **修法**：`original == null` 时就把我们的图返回（`param.setResult(preview)`，`:41/:91/:149/:192/:236`）；`t8r` 额外 `Xp.setField(param.thisObject,"f53958zy",replacement)`（`:238`），因为宿主把这个字段也当图片源。
- **证据**：【支持】`history/01` §3.3 记录 b1c "个性化页两张卡片彩色、未复现灰白"，但同处注明 `tm uf replaced` / `tm ni7 replaced` 日志只剩更早构建的记录 → 日志证据缺失。**本次未在设备上复跑该项**，所以状态是"代码已改 + 历史截图支持"，不是"当轮实测复核"。

### 3.4 已知风险

- 宿主可能 `recycle()` 我们返回的 bitmap（代码注释 `AodWallpaperPreview.java:283-287` 明说了 `BitmapUtil.fu4` 会 recycle），所以缓存实例一律 copy 出手。
- `ni7` 是"先写 layer 再返回"的方法，after-hook 改返回值可能无效（`features/01` §6.3 同结论）；真正开关是 `alive(context)`。

### 5.2 截图对照（最快的判据）

- 主页三张卡：**息屏必须是"黑底 + 球 + 时钟"**，锁屏是整屏壁纸，桌面是解锁后的样子。
  若"息屏==锁屏"逐像素相同 → 就是 Cosmic palette 回归（`features/03` §3.3），不是 UI 问题。
  【实测】`troubleshooting/02` §12.9 的差分：`aod vs lock` 平均差 4.17，`aod vs home` 14.74。
- 个性化页：两张卡应是彩色实拍图，不是灰白。灰白 = `toq`/`uf` 没被替换（先看 hook count 日志是不是 0）。

### 5.3 失败模式

| 现象 | 最可能的原因 | 先查 |
|---|---|---|
| 个性化页没有 AliveHS 卡片 | 宿主类/锚点 id 变了；`themeManager` 没勾作用域；注入时机早于卡片创建 | `PersonalizeEntry` 的 warn 日志；重试窗口只有 ~1.44s |
| 卡片在但点了没反应 | `HomeActivity` 未导出/未安装；`startActivity` 抛异常 | `personalize: open home failed` |
| 主页三卡全黑 | 没有小米包且 `RenderLoop` 起不来（EGL/图源） | `EGL init`、`loadPhoto`（见 `features/03` §7） |
| 主页卡片和真机不一致 | 卡片走 `RenderLoop` 的 APPLIED 场景，相机/时钟位置不参与 | 先确认该卡是不是小米包形态（有包就是静态图） |
| 个性化缩略图灰白 | `toq/uf` hook 未命中或 `alive()` 为 false | `tm … hook count=0`、`AodWallpaperMode.alive` |
| 个性化缩略图是旧图 | 缓存戳没变（文件 mtime/length 相同） | `AodWallpaperPreview.preview()` 的 stamp 逻辑 |
| 打开个性化页卡顿/闪退 | 缩略图尺寸过大（未按原尺寸缩放） | `scaleOrRecycle` 是否命中；原结果尺寸是否异常 |

### 5.4 取证命令

```bash
adb shell am start -a android.intent.action.VIEW -d 'theme://zhuti.xiaomi.com/personalize'
adb logcat -d -s AliveHSHooks | grep -E 'personalize|tm (uf|ni7|shots|lock|desk)'
adb shell dumpsys wallpaper | head -20     # 确认当前壁纸是不是 CleanWallpaper
```
