# 05 构建、安装、测试流程

> 目标：任何人按本文件可以从干净工作区构建、安装、复现问题、收集证据，不靠记忆。
> 所有命令默认在 Git Bash / MSYS 下执行；路径按当前机器。

## 1. 前置检查

```bash
cd /c/Users/ybybabab/app/项目开发/HyperAlive

git status --short
git log -5 --oneline
ls -l .tmp/build/libalive_clean.so
ls -l dist/AliveHS-0.1.0-arm64-v8a.apk
```

要求：

- 工作区改动已知；不要在有大量未解释修改时构建发布包；
- `.tmp/build/libalive_clean.so` 存在（native 库）；
- 磁盘空间足够（APK 约 308MB，构建中间产物数 GB）；
- 设备已连接、解锁、root 可用。

## 2. 构建

### 2.1 标准命令

```bash
export JAVA_HOME='C:/Users/ybybabab/app/pcl/JAVA21/graalvm'
export ALIVEHS_NATIVE_SO='.tmp/build/libalive_clean.so'
python3 tools/build_release.py --no-checks
```

说明：

- `--no-checks` 是必须的：`check_layout.py` 引用已删除的 `AodTransitionWindow` 等类，且 `CHECKS` 列表里另有 7 个脚本不存在。这不是“跳过质量”，而是当前检查器本身坏了；修好检查器后再恢复。
- 构建脚本内部：`aapt2 → javac → D8 → zipalign → apksigner`。
- `javac` 使用 `sources2.txt`（约 242 行）；源码新增/删除后要确认该文件更新。
- 构建日志在 `.tmp/` 或终端；失败先看第一条 `error:`，不要被后面的 `FAILURE` 淹没。

### 2.2 构建成功判据

```bash
sha256sum dist/AliveHS-0.1.0-arm64-v8a.apk
stat -c '%s %n' dist/AliveHS-0.1.0-arm64-v8a.apk
ls -l dist/SHA256SUMS dist/build-report.json 2>/dev/null
cat dist/SHA256SUMS 2>/dev/null
```

当前 b1c：

```text
b1c98f7401b3b0fdaece5af3f86bffe373f736442e4458f3393480cee05cb36c
308625742 bytes
```

> 历史坑：构建失败但 `adb install` 仍可能输出 `Success`（装的是旧包/半包）。**必须核对 APK SHA 和设备上的 APK**，不能只看 install。

### 2.3 常见构建错误

| 错误 | 原因 | 处理 |
|---|---|---|
| `check_layout.py` 引用了不存在的类 | 检查器过期 | 用 `--no-checks`；修检查器 |
| `sources2.txt` 找不到新类 | 源码列表没更新 | 重新生成/更新 sources2 |
| `javac` 报 `cannot find symbol` | 新类没进 sources2，或 API stub 不匹配 | 查 `sources2.txt`、`android.jar` |
| D8 报 duplicate class | 依赖重复/旧 class | 清 `.tmp/build`、检查 assets/libs |
| `apksigner` 失败 | keystore/密码/路径 | 查构建脚本签名配置 |
| APK 体积异常 | assets 未打包/重复 | 对比 308MB 基线 |

## 3. 安装

```bash
ADB="$LOCALAPPDATA/Android/Sdk/platform-tools/adb.exe"
D=9eb96e8a
APK=dist/AliveHS-0.1.0-arm64-v8a.apk

"$ADB" -s $D install -r "$APK"
```

### 3.1 安装后核对

```bash
# 设备上的 APK 路径/哈希（需要 root）
"$ADB" -s $D shell pm path org.aliveclean
"$ADB" -s $D shell su -c 'sha256sum /data/app/.../base.apk'

# versionName/versionCode
"$ADB" -s $D shell dumpsys package org.aliveclean | grep -E 'versionName|versionCode'
```

哈希应与 `dist` 一致。若不一致，重装/查多用户/查 split。

### 3.2 重启

```bash
"$ADB" -s $D reboot
```

等开机完成：

```bash
"$ADB" -s $D wait-for-device
"$ADB" -s $D shell getprop sys.boot_completed
```

> 动了 `system` 作用域代码，必须整机重启；只重启 SystemUI 不够。

## 4. 重新应用项目壁纸

安装/重启后，系统壁纸可能回退到 MIUI `ImageWallpaper`，`full_screen_aod_on` 可能变 0。先解锁，再执行：

```bash
# 取设备上的 APK 路径
APK_PATH=$("$ADB" -s $D shell pm path org.aliveclean | sed 's/package://' | tr -d '\r')
echo "$APK_PATH"

"$ADB" -s $D shell su 1000 -c \
  "CLASSPATH='$APK_PATH' /system/bin/app_process /system/bin org.aliveclean.SceneApply"
```

预期：

```text
SCENE_APPLIED
```

检查：

```bash
"$ADB" -s $D shell dumpsys wallpaper | head -40
"$ADB" -s $D shell settings get secure doze_always_on
"$ADB" -s $D shell settings get secure full_screen_aod_on
```

预期：

- system 壁纸组件 = `org.aliveclean/.CleanWallpaper`；
- `doze_always_on=1`；
- `full_screen_aod_on=1`。

若失败：

- 含 `AMBIENT_WALLPAPER` → 勾 `system` 作用域 + 重启；
- 含 `RUNNING_LOCKED` → 解锁后重试；
- 超时 → root 授权/子进程卡住；
- 成功但壁纸没变 → 查 `dumpsys wallpaper`、锁屏槽、多用户。

## 5. 测试环境固定

每次 AOD/动画测试前，固定这些状态并记录：

```bash
"$ADB" -s $D shell settings get secure doze_always_on
"$ADB" -s $D shell settings get secure full_screen_aod_on
"$ADB" -s $D shell dumpsys wallpaper | head -40
"$ADB" -s $D shell dumpsys deviceidle | grep -i doze
```

要求：

- 屏幕亮度/自动亮度固定；
- 不息屏超时干扰（测试时手动按电源键）；
- 不用动态壁纸/第三方锁屏；
- 系统主题固定；
- 记录是否充电（充电可能影响 doze）；
- 记录 AOD 显示模式（始终显示/点击 10 秒/智能/定时）。

## 6. 测试矩阵

### 6.1 AOD 基础

| 用例 | 操作 | 预期 |
|---|---|---|
| AOD 开启 | 设置 doze=1，应用项目壁纸 | 设置页 AliveHS；full=1 |
| AOD 关闭 | doze=0，应用项目壁纸 | full=0；息屏全黑；无注入 |
| 稳定球 | 电源键息屏，等 2/6/12/18 秒 | 球持续存在，时钟在球上/下正确层级 |
| 转场 | 桌面→息屏，录屏 | 缩球平滑，无长时间黑屏 |
| 唤醒 | AOD→电源键 | 球展开/壁纸恢复，无残留 |
| 指纹 | 真实手指按压 | 时钟/指纹区域正常，不消失 |

### 6.2 壁纸切换

| 用例 | 操作 | 预期 |
|---|---|---|
| 项目→系统 | 主题壁纸切系统静态 | AOD 行恢复原生；full 恢复原值；无球残留 |
| 系统→项目 | 应用项目壁纸 | AOD 行 AliveHS；full=1 |
| 项目→系统→项目 | 连续切换 | 每一步 full/样式正确；无“自定义”错乱 |
| 重启后 | 重启，不重新应用 | 壁纸仍项目/或按系统行为；full 不被错误写 1 |

### 6.3 个性化

| 用例 | 操作 | 预期 |
|---|---|---|
| 打开个性化 | `theme://zhuti.xiaomi.com/personalize` | 两张卡片彩色 |
| 滚动/重建 | 滚动、返回再进 | 仍彩色，不灰白 |
| 切系统壁纸 | 切回系统 | 卡片显示系统壁纸，不残留项目图 |
| 预览点击 | 点锁屏/桌面卡片 | 不崩溃；进入正确页面 |

### 6.4 应用壁纸

| 用例 | 操作 | 预期 |
|---|---|---|
| 正常应用 | 选场景→应用 | `SCENE_APPLIED`；桌面变 |
| 未勾 system | 取消 system，重启，应用 | 明确报缺少系统框架 |
| 锁屏应用 | 锁屏时应用 | 提示/失败，不崩溃 |
| 安装后应用 | 装新 APK 后直接应用 | 成功或明确错误；full 正确 |

## 7. 日志与证据

### 7.1 清日志/抓日志

```bash
"$ADB" -s $D logcat -c
# 复现
"$ADB" -s $D logcat -d -v time > .tmp/logs/run-$(date +%H%M%S).log
```

过滤：

```bash
grep -E 'AliveHSAod|AliveClean|AliveHSHooks|AndroidRuntime|FATAL|am_crash' \
  .tmp/logs/run-*.log
```

### 7.2 截图/录屏

```bash
"$ADB" -s $D exec-out screencap -p > .tmp/screenshots/aod-$(date +%H%M%S).png
"$ADB" -s $D shell screenrecord --time-limit 10 /sdcard/aod.mp4
"$ADB" -s $D pull /sdcard/aod.mp4 .tmp/screenshots/
```

注意：

- 录屏可能不显示 AOD 注入的 secure 层；`screencap` 更可靠；
- 稳态测试要截多个时间点，不要只截转场；
- 文件按时间命名，避免覆盖。

### 7.3 关键日志含义

| 日志 | 含义 |
|---|---|
| `AliveHSHooks: aod mode ->1` | 模块把 full_screen_aod_on 写 1 |
| `AliveHSHooks: aod mode restored=0` | 模块恢复原值 0 |
| `AliveHSAod: AOD scene skipped: AOD is disabled` | 用户关了息屏显示 |
| `AliveHSAod: AOD scene skipped: wallpaper is not ours` | 壁纸判定不是项目 |
| `AliveHSAod: injected into the AOD view` | surface 注入成功 |
| `AliveClean: aod photo from provider 1200x2608` | AOD 图来自 provider |
| `AliveClean: aod provider returned no bitmap` | provider 失败，可能黑屏 |
| `tm uf replaced 680x1509` | 个性化缩略图替换成功 |
| `tm ni7 replaced 1200x2608` | 预览替换成功 |
| `full aod hooks=...` | AodFullScreen 安装 hook 数 |
