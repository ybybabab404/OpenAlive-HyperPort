## 3. 壁纸应用数据流

```text
MainActivity 选择场景
  → SceneOptions 写 SharedPreferences("scene")
  → SceneApply.apply(context)
      → AodWallpaperMode.enter(context)        # 先捕获原 full_screen_aod_on
      → su 1000 app_process SceneApply.main
          → ActivityThread.systemMain()
          → aodSwitchFromShell() ? enter : skip
          → setWallpaperComponentWithFlags(CleanWallpaper, SYSTEM|LOCK)
          → 校验 getWallpaperInfo()
          → ModuleActivation.request(context)
          → SCENE_APPLIED
      → 失败：restore + 报错
```

关键点：

- **先 capture 再 apply**：顺序反了会把 MIUI 已改写的 1 当成原值；
- `AodWallpaperMode` 的 restore 键在 `system` 进程读不到 Settings 时走 `su 0 settings`；
- 应用成功后如果 AOD 开关是关的，会立即 restore。

## 4. 壁纸渲染数据流

```text
WallpaperService.Engine (CleanWallpaper)
  → onSurfaceChanged/onVisibilityChanged
  → RenderLoop.attach(surface, w, h)
  → Choreographer/Handler 每帧:
       updateScene (effects/gyro/video)
       NativeScene.render
       EGL swap
  → SurfaceControl 上屏
```

`CleanWallpaper` 关键输入：

| 输入 | 处理 |
|---|---|
| `ACTION_SCREEN_OFF` | `send(0,false)` / `refreshVisibility` |
| `ACTION_SCREEN_ON` | `refreshVisibility` |
| `ACTION_USER_PRESENT` | `refreshVisibility` |
| `android.wallpaper.goingtosleep` | 提前 `send(0,true)`，抢在 SCREEN_OFF 前启动转场 |
| `action_alive_aod` | `ambient=true; send(0,animate)` |
| `apply_scene`/`SceneChannel` | reload options |

`RenderLoop` 关键：

- `loadPhoto(name, primary)`：优先 `AodWallpaperProvider.PHOTO`；失败后本进程文件；旧 SystemUI 共享缓存已删；
- `onFirstFrame(Runnable)`：首次 `swap` 成功回调，`AodSurface` 用它启动 alpha 淡入；
- `mode(0)`：AOD 场景；`update` 驱动 `v0`（球体进度）；
- `Diagnostics.TRACE`：`frame dt/vsync gap/draw gap eff ren sw v0`。

## 5. AOD 注入数据流

```text
MiuiDozeService.onDreamingStarted
  → MIUI 创建 AODView
  → HyperOsAod 的 AODView attach hook
  → scheduleAttach(root)  [950ms]
  → attach(root):
       aodEnabled? aodSceneEnabled? AodWallpaperMode.alive?
       findInnerAod(root)
       new AodSurface(context)
       target.addView(surface, min(1, childCount))
  → SurfaceTexture available:
       new RenderLoop(moduleContext)
       loop.onFirstFrame(... alpha 1)
       loop.mode(0); loop.attach(surface)
  → 稳定 AOD
```

### 5.1 关键条件

```java
if (!aodEnabled(context)) { detach(); return; }
if (!aodSceneEnabled(context)) { detach(); return; }
if (!AodWallpaperMode.alive(context)) { detach(); return; }
```

任一 false 都不会有球。

### 5.2 关键死代码/风险（2026-11-15 22:40 复核更新）

- `supervise(root, surface)` 定义在 `HyperOsAod.java:199`，但**全仓无调用点**（死代码）。细节：300ms/轮、最多 100 轮；`getParent()==null` 连续 8 次 miss 才重挂。
- `attach` 的早退判据是 `existing.isAttachedToWindow() && existing.isShown()`（`HyperOsAod.java:149`），不检查 alpha、是否出帧、parent 是否为 inner AODView。
- AODView **构造器**被 hook（两个类名：`com.android.keyguard.widget.AodView`、`com.miui.aod.AODView`）。所以“AODView 被重建”会重新触发 `scheduleAttach`；“只是被清空子 View”才不会。判定 H1 时必须先分清这两种情况。
- `installDoze` 在 `onDreamingStarted/onDreamingStopped` 里直接调 `AodOverlay.show/hide`（`HyperOsAod.java:44-68`），**AodOverlay 不是“没在用的兜底”**，而是每次息屏首选的注入入口，失败才退 2038 窗口。
- `AodOverlay.show` 打印的 `injected into the AOD view` **不能证明注入成功**：`injectIntoAod()` 只判 `aodRoot != null` 就返回 true。真正证明注入的是 `Trace` 的 `T04 surface#create`（默认 `Diagnostics.TRACE=false`，需要临时打开才能看到）。
- `onSurfaceTextureDestroyed` / `onDetachedFromWindow` 都会清 `liveSurface`，但 AODView 重建时不一定走它们。

## 6. 全屏 AOD hook 地图

`AodFullScreen.install(loader, settingsProcess)`：

| 进程 | hook | 目的 |
|---|---|---|
| `com.miui.aod` | `Utils.isSupportFsAod` | 显示 AliveHS 行 |

## 7. AOD 设置页地图

`AodSettingsGuard`：

- hook AOD 设置 Activity 的 `onResume`/`onViewAttachedToWindow`/`setContentView`；
- 找 `aod_resting_screen_style` + `aod_resting_screen_choose`；
- `uiAlive` 为 true 时包装 `LabelAdapter` + `lock`；
- 否则 `unbind`。

数据：

- `Saved(row, spinner, adapter, labelAdapter)`
- `LabelAdapter` 的 `labelPosition` = 原生首项之后（通常 1）
- `lock` 禁触摸/点击/焦点。

失败点：

- MIUI 重建 adapter → `applyLabel` 检测 `current != saved.adapter`，重新包装；
- 页面未重建 → 切壁纸后仍显示 AliveHS；
- `uiAlive` 误判 → 行不出现/不消失。

## 8. 个性化缩略图地图

`AodWallpaperPreview` hooks：

| 方法 | 用途 |
|---|---|
| `TemplateApiImpl.getPlaceholderWallpaper` | 占位图 |
| `TemplateApiImpl.ni7` | 预览 wallpaper layer |
| `TemplateApiImpl.uf` | 预览 bitmap |
| `Screenshots.t8r` | 截图/卡片 |
| `LockScreenWpTool.toq` | 锁屏预览 |
| `DeskWpTool.toq` | 桌面预览 |

流程：

```text
ThemeManager 请求预览
  → hook 命中
  → alive = AodWallpaperMode.alive(context)
  → preview = fromProvider() or template file
  → if original == null: replacement = preview
     else: replacement = scaleOrRecycle(preview, original.w, original.h)
  → param.setResult(replacement)
  → t8r 额外 setField(f53958zy, replacement)
```

关键修复：

- `original == null` 不再 return；
- cached bitmap 防御性 copy；
- `scaleOrRecycle` 回收缩放副本；
- `ni7` 的 after-hook 改返回值可能无效（它先把图写 layer），必要时 before-hook。

## 9. 景深/指纹地图

`KeyguardDepthHider`：

- hook `updateKeyguardElementsVisibility` before：置 `isActualDisplayDepth=false` + clear；
- hook `isNeedPreHideDepth`：返回 false；
- 目的：避免 native 在 after-hook 前已按“双层景深”布局。

`KeyguardTouchRelay`：

- 把锁屏触摸/按压转发；
- 与 `AodFullScreen` 的 doze 状态配合。

验证限制：真实指纹必须人工；adb 虚拟指纹不能证明时序。

## 12. 线程/时序风险

- `HyperOsAod` 的 `attach` 在 SystemUI 主线程；`postDelayed` 200/950ms；AODView 可能在这期间重建；
- `RenderLoop` 在 TextureView 的 SurfaceTexture 线程/GL 线程；
- `AodSurface` 的 `onFirstFrame` 回调 post 到主线程再 alpha；
- `AodFullScreen` 的 hook 在 system_server/SystemUI/AOD 多进程，静态字段不共享；
- `AodWallpaperMode` 的 restore 探针用主线程 Handler，5×1s；
- `SceneApply` 子进程 `ActivityThread.systemMain()` 的 Settings 可能 stale，所以用 shell 读 `doze_always_on`。

## 13. 代码审查重点

- 任何 `hookAllMethods` 失败是否只 warn 不阻断？
- 静态字段是否跨进程误用？
- `WeakReference` 是否在 GC 后变 null 导致 detach？
- `Bitmap` 是否被宿主 recycle？
- `SurfaceTexture` 销毁后 `liveSurface` 是否清理？
- `AODView` 重建后是否重挂？
- `Settings.Secure` 读写是否在主线程/高频？
- 是否在 `draw`/`onFrame` 里做 IO？
- 是否有未关闭的 `ParcelFileDescriptor`/`Process`？
