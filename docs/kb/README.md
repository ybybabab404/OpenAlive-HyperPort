> 这是项目的“说明书 + 排错手册 + 交接底稿 + AI 协作提示词”。
> 目标不是重复旧交接文档，而是把**已经核实的事实、推断、历史版本、失败链路**分开记录，防止下一任 AI 继续被旧文档里的过时结论误导。

## 2. 证据级别（必须标注）

本 KB 的每条关键结论尽量带一个级别，禁止把推断写成事实：

- **【已验证】**：有当前设备截图、录屏、logcat、`settings get`、文件哈希、构建日志等直接证据。
- **【高置信推断】**：源码链路 + 历史日志能推出，但当前设备还没有完成最终复现。
- **【待验证】**：用户报告、旧文档、团队报告或只在一个旧版本上看到，尚未在当前构建确认。
- **【历史】**：只在过去版本成立；不能直接用于当前版本。

写文档时使用这样的格式：

```text
结论：【已验证】当前 b1c 在 doze_always_on=0 时，真实电源键熄屏截图全黑，full_screen_aod_on=0。
证据：.tmp/screenshots/b1c_aod_off.png；logcat "aod mode restored=0"。
```

## 3. 实时维护规则

每次改代码、构建、安装、复测、发现新 bug，必须同步更新本 KB：

1. 改了行为 → 更新 `02-功能清单与实现.md`
2. 改了 bug 状态/根因 → 更新 `03-已知Bug与排错.md`
3. 新构建/新 SHA → 更新 `06-版本与回归历史.md`
4. 改了作用域/权限/安装方式 → 更新 `04-*`
5. 改了构建/测试步骤 → 更新 `05-*`
6. 改了源码结构/函数 → 更新 `07-*`
7. 系统属性、Secure 设置、删除文件、安装/卸载系统应用 → 更新 `09-*`
8. 用户提出新要求 → 先更新 `00-*`，再改代码

**不允许只在聊天里说“已验证”，却不落盘。** 下一任 AI 看不到聊天记录，只看到文件。
