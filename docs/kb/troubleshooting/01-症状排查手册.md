## 1. 证据分级（写结论前先给自己定级）

沿用 `docs/kb/README.md` §2；引用本文件的判定时，**级别要一起带走**。

| 级别 | 什么算 | 什么不算 |
|---|---|---|
| 【实测】 | 当前设备/当前构建的原始输出：`settings get`、`dumpsys`、logcat 原文、哈希、逐帧逐点数值（`ratio=0.43→0.11`、亮像素 86/800） | 你以为它会输出什么 |
| 【日志】 | 有 logcat 原文，但只反映一次现象 | 找不到原始文件的日志（`02-*` 已把多条"已验证"因此降级） |
| 【支持】 | 截图/录屏/用户肉眼确认能证明方向 | 拿转场帧证明"稳定态有球"（`b1c` 时代最大误判） |
| 【推断】 | 读代码/反编译得出，设备未复现 | 拿推断当结论去改代码 |
| 【证据不足】 | 只有旧文档、旧交接、单次观察 | 写成"已验证" |

三条硬规矩：① **改完现象变了 ≠ 找到原因**（`02-*` §12.5→§12.6：改完双层没了，其实把动画也改没了）；② `adb install` 的 `Success`、构建输出的 `sha=` 都不是证据；③ 找不到原始日志就写【证据不足】，不许补一条看起来很真的日志。

## S1 模块完全不生效（任何功能都不动）

**现象**：装好了也重启了，AOD/个性化/应用壁纸全无变化，logcat 里没有一条 `AliveHS*`。

**可能原因（按概率）**
1. **作用域没勾或勾错**（最高频）。必须勾四个，**按包名认**：`com.android.systemui`、`com.miui.aod`、`com.android.thememanager`、`system`（"系统框架"）。**`android`（"安卓系统"）不要勾**——`onPackageLoaded()` 里对 `"android"` 直接 `return`，勾了不装任何 hook，只扩大注入面。
2. **勾了 `system` 却没整机重启**：API 102 下只有 system_server 必须重启手机，其余三个 `killall` 即可。
3. **进程没换**：`am force-stop com.android.systemui` 有时不换 PID（历史踩到，导致 AOD 关闭测试误判）；用 `killall` 并核对 PID。
4. **LSPosed 进了安全模式**（连续崩溃后全部模块失效）。
5. **旧包/半包**（见 S12）或模块被禁用；版本不匹配（本机已验证组合：API 102、Android 17、`minSdk=28`）。

**先查什么**
```bash
"$ADB" -s $D logcat -d -s AliveHS     # 期望 module loaded process=... api=102 与各进程 loaded into <pkg> pid=
"$ADB" -s $D shell ps -A | grep -E 'systemui|miui.aod|thememanager|system_server'
"$ADB" -s $D shell su 0 killall com.android.systemui
"$ADB" -s $D shell su 0 killall com.miui.aod
"$ADB" -s $D shell su 0 killall com.android.thememanager
"$ADB" -s $D shell ps -A | grep systemui      # 确认 PID 真的变了
"$ADB" -s $D reboot && "$ADB" -s $D wait-for-device
"$ADB" -s $D shell getprop sys.boot_completed # 期望 1（system 作用域只能靠整机重启）
"$ADB" -s $D shell su 0 tail -100 /data/adb/lspd/log/modules.log
"$ADB" -s $D logcat -d -v time | grep -E 'FATAL EXCEPTION|am_crash|LSPosed'
```
判读：`loaded into <pkg> pid=` 的 PID 与 `ps` 一致才算换上新代码；只有 `module loaded` 没有某进程的 `loaded into`，就是那个作用域没生效。

**涉及**：`CleanHooks.java`（`onSystemServerStarting`/`onPackageLoaded`/`handle`）；产物侧 `tools/build_release.py` 写入的 `scope.list`、`app/res/values/strings.xml` 的 `xposed_scope`、`module.prop`；说明见 `troubleshooting/03-*` §1–§2、§8。

**版本**：【实测】四个作用域齐 + 整机重启是 `ff49027` 起每次验证的前提；【历史】`08a0/73b54/0ecc/f2d2/5f41/b920` 无 APK 存档，**不能做回滚对照**（`build/01-*` §9.4）。

**下一步**：贴 `grep 'loaded into'` 与 `ps` 的 PID；这两样没有，别动代码。

## S2 应用壁纸失败 / 点了没反应

**现象**：点"应用"转圈、报错，或提示成功但桌面壁纸没变。

**可能原因（按概率）**
1. **没勾 `system`（系统框架）**——最常见。`SceneApply` 用 `su 1000` + `app_process` 调 `WallpaperManager.setWallpaperComponentWithFlags`，需要 `AMBIENT_WALLPAPER`；没勾时报 `SecurityException: ... does not have android.permission.AMBIENT_WALLPAPER`，代码会翻成"缺少「系统框架」作用域：请在 LSPosed 里给本模块勾选「系统框架」再重启手机"。
2. **勾了 `system` 但没重启手机**（system_server 仍旧代码）。
3. **锁屏态执行**：`app_process` 读不到 `Settings.Secure`，表现为失败/超时。**不要 grep `RUNNING_LOCKED`——源码里没有这个串**；先解锁再应用，失败就贴子进程原始输出。
4. **root 未授权 / 子进程卡住**：`su` 弹窗没点，或 25s `waitFor` 超时。
5. **非主用户**：`Process.myUid()/100000 != 0` 时直接抛"目前仅支持主用户"。
6. 装包/重启后系统壁纸回退成 MIUI `ImageWallpaper`，需重新应用（平台行为，不是 bug）。

**先查什么**
```bash
# 先解锁！然后手动跑一遍（最快判定，成功输出含 SCENE_APPLIED）
APK_PATH=$("$ADB" -s $D shell pm path org.aliveclean | sed 's/package://' | tr -d '\r')
"$ADB" -s $D shell su 1000 -c "CLASSPATH='$APK_PATH' /system/bin/app_process /system/bin org.aliveclean.SceneApply"
"$ADB" -s $D shell dumpsys wallpaper | head -40      # mWallpaperComponent 应为 org.aliveclean/.CleanWallpaper
"$ADB" -s $D shell settings get secure doze_always_on
"$ADB" -s $D logcat -d -s AliveHS AliveHSHooks | grep -E 'aod mode|ambient permission|SCENE'
```
判读：`ambient permission: granted via ...` 说明权限 hook 生效；`aod mode enter skipped: AOD is disabled` 是用户关了 AOD（正常）。失败判据是"退出码非 0 或输出不含 `SCENE_APPLIED`"。

**涉及**：`SceneApply.java`（`apply()` 与子进程 `main`）、`AodWallpaperMode.java`（`enter`/`restore`/`alive`）、`CleanHooks.java`（`checkPermission` 放行）、`CleanWallpaper.java`。

**版本**：【实测】应用路径自 `08a0` 起反复验证；【实测】装包后重启需重新 `SceneApply`；【推断】"没勾 system 必失败"由代码 + `checkPermission` 双重支撑，但**具体报错一律以子进程原始输出为准**。

**下一步**：贴子进程原始输出 + `mWallpaperComponent`；含 `AMBIENT_WALLPAPER` 就去勾"系统框架"并重启手机。

## S3 息屏不显示球 / 息屏全黑 / 息屏只有时钟

**现象**：三种，先分型再查。A 全黑（连时钟都没有）；B 只有时钟没球；C 球在但发黑/大小位置怪。

**可能原因（按概率）**
1. **截图时机错**：`mState=DOZE_SUSPEND` 截出来**必然全黑**，不是模块问题（`02-*` §9.5 踩过）。只有 `DOZE` 的截图有意义。
2. **AOD 被关**：`doze_always_on=0` 或 `scene.xml` 的 `aod=-1` → `AOD scene skipped: AOD is disabled`。
3. **壁纸不是我们的**：`alive()` 只看 system 槽 `getWallpaperInfo()`，系统静态壁纸返回 null → `AOD scene skipped: wallpaper is not ours`。
4. **注入没成功**：`injectIntoAod()` 200ms × 25 次重试耗尽 → `AOD injection gave up: no AODView after ... tries`（`T06` 需 `Diagnostics.TRACE=true`）。
5. **注入了但 alpha 停在 0**：`alpha watchdog fired, alpha=0.0`（看门狗 1500ms 把 alpha 拉起，"拉起 alpha"≠"有内容"）。
6. **首帧不来的根因是 doze 期间没有 vsync**：`framePosted` 卡死使 `schedule()` 全成空操作；兜底日志 `vsync watchdog: drawing without Choreographer`。
7. **图源空 → 黑帧**（不透明 TextureView 直接盖黑）：`aod provider returned no bitmap` / `aod photo from provider WxH`。
8. **被盖住/层级变了**：注入点在 AODView index 1（index 0 不透明黑底、index 2 `AodContainerView`），用 `T12` 打印子 View 顺序核对。
9. **别指望 2038 悬浮窗**：`AodOverlay` 窗口在 doze 下被 WMS 策略隐藏（`mPolicyVisibility=false`），本机这条路是死的。

**先查什么**
```bash
"$ADB" -s $D shell input keyevent 26
"$ADB" -s $D shell dumpsys display | grep mState=            # 必须 DOZE，不是 DOZE_SUSPEND
"$ADB" -s $D exec-out screencap -p > .tmp/screenshots/aod-$(date +%H%M%S).png
# 量化"有没有球"：裁 y=200–700、缩到 40×20 数亮像素；失败 0/800，正常 86–129/800
"$ADB" -s $D logcat -d -s AliveHSAod AliveClean | tail -100
# 关心：AOD scene skipped / injection gave up / T04 surface#create / T05 texture#available 1200x2608
#       T13 surface state alpha=1.0 parent=AODView / alpha watchdog / vsync watchdog / aod photo from provider
"$ADB" -s $D shell settings get secure doze_always_on
"$ADB" -s $D shell su 0 cat /data/data/org.aliveclean/shared_prefs/scene.xml | grep -E 'aod|photo'
```
注意：`injected into the AOD view` **不是**注入成功的证据（`AodOverlay.show()` 只要 `aodRoot != null` 就打）；真正证明的是 `T04`→`T05`→`T13`。

**涉及**：`HyperOsAod.java`（`attach`/`injectIntoAod`/`supervise`/`AodSurface`；`BALL_CENTER_Y=0.165`、`BALL_RADIUS=0.22`、alpha 看门狗）、`RenderLoop.java`（`loadPhoto`、`EGL init`、`vsync watchdog`）、`AodOverlay.java`、`AodWallpaperMode.java`、`AodFullScreen.java`、`Diagnostics.java`（`TRACE=false`）。

**版本**：坏 `b1c`/`4591c24`/`56e279f`（用户报无球，`alpha watchdog fired, alpha=0.0`【支持】）、`ba6e5de`（首帧不来【日志】）；好 `ff49027`（首次稳定球，25/45/65s【实测】）、`1095efd`（6 轮 86–124【实测】）、`338aae7`（正式口径 3 轮 90–115【实测】）、`58e0004`（亮像素 128/800【日志】）。**不要用 `stable-anim-2026-11-02` 证明稳定球正常**（它只证明动画，`history/01-*` §3.4）。

**下一步**：给"`mState` 是否 DOZE + 亮像素数 + 最后 30 行 `AliveHSAod`"三样，才能分清**没注入**/**注入了被移除**/**注入了但内容黑**。

## S4 息屏预览显示成锁屏

**现象**：主页三张卡片里「息屏」与「锁屏」同一张画面；编辑页 `scene=0` 也是整屏壁纸，而真机息屏是黑底 + 顶部球 + 时钟。

**可能原因（按概率）**
1. **`RenderLoop.createScene()` 的 cosmic 分支 palette 映射回退**：被修掉的写法 `int palette = mode==0 ? 1 : mode;`（把 AOD 强行映射到 keyguard 调色板）；正确是 `int palette = mode;`。`85cfa94` 引入、`f2630bc` 修回。
2. **装的是修复前的包**（`85cfa94`~`96618ca` 之间）；主页卡片与编辑页共用一个 `RenderLoop`，所以两处一起错。
3. **编辑页读的是"已应用"的图而不是草稿**：`RenderLoop.loadPhoto` 的 provider 分支只在非预览时用——这会造成"预览跟你刚改的不一致"，与 palette 是两回事。
4. `aod=-1`（关掉息屏场景）时预览自然没有 AOD 形态。

**先查什么**
```bash
"$ADB" -s $D exec-out screencap -p > .tmp/screenshots/home-cards.png   # 三卡截图做差分
#   修复前：aod vs lock 平均差 4.17 ≈ 逐像素相同（aod vs home 14.74）
grep -n 'palette' app/java/org/aliveclean/RenderLoop.java             # 当前应为 int palette=mode;
"$ADB" -s $D shell dumpsys display | grep mState=                     # 真机对照要在 DOZE 下截图
```

**涉及**：`RenderLoop.java`（`createScene()` cosmic 分支）、`CosmicMotion.java`（调色板 `{"aod","keyguard","unlock"}`，aod 几何即"缩放 0.22 的球"）、`HomeScenePreview.java`/`MainActivity`。

**版本**：【实测】坏：含旧映射的包（`96618ca`/`af66f52`/`56a0fb5` 时期，具体起始构建【待验证】）；【实测】好 `f2630bc`（卡片=黑底+球，编辑页一致；真机球略小属预期）；【支持】用户 2026-11-16 18:00 确认"正常了"。回退即把 `int palette=mode;` 改回 `mode==0?1:mode`（`02-*` §12.9）。

**下一步**：`grep -n 'palette' RenderLoop.java`；若已是 `int palette=mode;`，转去看 S9（草稿/provider 那条）。

## S5 息屏→桌面双层、残影、动画丢失、壁纸放大跳变

**现象**：已解锁状态下唤醒时两层画面叠约 1 秒收敛；或修完之后转场变"瞬移/没有"；或放大过程跳变。（**锁屏态唤醒走锁屏动画，别测错路径**。）

**可能原因（按概率）**
1. **AOD 层与桌面层交叉淡入太长**（主因）：诊断实测 `wake t=722 ratio=0.43/0.00/0.57` → `t=1046 ratio=0.11/0.00/0.89`。锁屏选了纹理时两层差别大→看见双层；锁屏选"无"时几乎一样→看不见。**锁屏层权重恒为 0**，不是 glass 图层被叠上来。
2. **条件是"启航（`aod==0`）+ 离开息屏 + 锁屏带纹理"**；别的样式不出现——这条差分事实就是 `02-*` §12.8 的定位依据。
3. **与 AOD 注入无关**：把 `scene.xml` 的 `aod` 改 `-1`（完全不注入 surface）后用户复测"球还在、双层还在"，双层来自壁纸引擎的 `mode 0→2→1` 三次构图切换。
4. **动画丢失**：曾为修双层把 `lens()` 时长清零，结果"单层了但动画也没了"（§12.5）；`SceneMotion` 已整文件还原基线，若又瞬移先查它被动过没。
5. **放大跳变**：【推断】与 150ms 特例（叠加期极短）或唤醒转场几何有关；**当前无逐帧证据，标【证据不足】**。

**先查什么**
```bash
"$ADB" -s $D shell dumpsys display | grep mState=                      # 确认是已解锁唤醒
"$ADB" -s $D shell screenrecord --time-limit 10 /sdcard/wake.mp4
"$ADB" -s $D pull /sdcard/wake.mp4 .tmp/screenshots/
grep -n 'blendDuration' app/java/org/aliveclean/SceneMotion.java
#   当前应有 if(aod==0&&previous==0&&next==2&&lock>=1)blendDuration=150;
```

## S6 系统壁纸与项目壁纸互切后 AOD 模式/样式没恢复

**可能原因（按概率）**

## S9 编辑器预览与实际不符 / 主体识别失败或很慢 / 导入照片很慢

**现象**：编辑页看到的和真机不一致；点「主体/背景」没反应或等很久；导入照片要等好几秒。
