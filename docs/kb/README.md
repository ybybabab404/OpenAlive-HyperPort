## 2. 证据级别（每条重要结论必须标注）

| 级别 | 含义 | 例子 |
|---|---|---|
| 【实测】 | 在当前设备/当前构建上跑出来、有原始输出 | `wake t=183 ratio=0.99 → t=333 ratio=0.03`；截图差分 4.17 |
| 【日志】 | 有 logcat/dumpsys 原文，但只反映一次现象 | `Surface: shown=false`、`supervise done, parent=...AODView` |
| 【支持】 | 截图/现象能证明方向，但没有逐点数值 | 用户确认"双层没了" |
| 【推断】 | 读代码得出、未在设备上验证 | "这个分支在小屏上会走到 X" |
| 【证据不足】 | 只有说法、没有原始证据 | 旧 HANDOVER 里未复核的"已验证" |

规则：**旧文档的"已验证"必须先复核**才能当事实；冲突时记录冲突并继续查，不要挑一个顺眼的。

## 4. 实时维护规则

1. **每次**构建/装机/复测/bug 状态变化/功能变化，更新对应文档（对照表见 `ai/02` §7）。
2. 新增文档要登记到本文件 §0 与 §1。
3. 结论必须带证据级别；没有证据的写【证据不足】。
4. 编码约定：`.md` 一律 UTF-8；`history/01-*` 是 UTF-8 **带 BOM + CRLF**，改它要保 BOM 与行尾。
5. 压缩上下文前，先把关键事实写进 `docs/kb/`；不要压缩 `00-原始要求与协作规则.md` §1 的原文。
6. 不要在文档里留"待补"占位超过一轮；当轮就要补齐或明确标注为未完成。

## 5. 术语速查

| 术语 | 含义 |
|---|---|
| AliveHS 样式 | 我们在系统 AOD 设置页插入并锁定的息屏样式行 |
| 球 | 息屏时壁纸被裁成椭圆显示在屏上部（`BALL_CENTER_Y=0.165`、`BALL_RADIUS=0.22`） |
| 启航 / 长虹 | 项目内的壁纸纹理样式名（锁屏/桌面纹理选择） |
| 双层 | 息屏→桌面切换时两层画面同时在场约 1 秒产生的重影 |
| AOD 全屏 | 系统"全屏息屏显示"能力，键为 `full_screen_aod_on` |
| scene.xml | 已应用场景配置（`SceneOptions.APPLIED`），键见 `features/03` §1 |
| draft | 编辑器里的草稿配置（`SceneOptions.DRAFT`），应用后才写进 scene.xml |
